详细描述

B+树内部节点类

B+ 树内部节点 - 存储路由键并引导搜索流量至正确的子节点

WHY: 为什么需要B+树内部节点？

B+树索引系统需要专门的内部节点来构建树形结构：

  • 内部节点存储索引键和子节点指针，建立多层索引
  • 内部节点不存储数据，只存储路由信息，减少内存占用
  • 内部节点的多路分支特性决定了B+树的扇出和深度
  • 内部节点的分裂和合并操作决定了树结构的动态平衡

内部节点的核心价值：

  1. 索引路由：提供从根到叶子的快速路径查找
  2. 空间效率：只存储键值和指针，不存储实际数据
  3. 平衡维护：通过分裂合并保持树的平衡性
  4. 查询优化：减少磁盘访问次数，提高查询性能

🏗️ 设计模式：组合模式(Composite Pattern)

内部节点作为树结构的一部分：

  • 继承节点基类：统一接口和基础功能
  • 实现索引特化：键值存储和子节点管理
  • 参与树操作：分裂合并的内部节点逻辑
  • 支持递归遍历：树形结构的深度优先访问

内部节点特化的设计考虑：

  • 键值有序：维护分隔键的有序性和唯一性
  • 指针管理：子节点指针的生命周期管理
  • 分裂策略：键值分配和子节点重组的策略
  • 合并条件：相邻节点合并的条件判断

WHAT: B+树内部节点 - 索引路由的核心组件

核心功能：

  • 键值索引管理：存储分隔键值，建立搜索路径
  • 子节点指针维护：管理子节点的页面引用
  • 路由查找操作：根据键值确定子节点方向
  • 分裂合并处理：节点大小的动态调整
  • 树结构平衡：维护B+树的平衡特性

数据结构设计：

  • 键值数组：有序存储的分隔键值集合
  • 子节点指针：指向子节点的页面ID数组
  • 键值映射：每个键值对应左右子节点的范围
  • 页面绑定：与磁盘页面的直接映射
  • 元数据管理：节点状态和边界信息

接口设计：

  • 子节点管理：InsertChild/RemoveChild操作
  • 路由查找：FindChildPageId确定搜索方向
  • 结构调整：Split/Merge处理节点重组
  • 状态查询：键值和指针的访问接口
  • 调试支持：内部状态的检查方法

HOW: B+树内部节点的实现机制和优化策略

数据组织架构：

  • 键值排序：严格有序的分隔键值数组
  • 指针对应：键值左右的子节点指针关联
  • 范围划分：每个子节点负责的键值范围
  • 边界处理：最小值和最大值的特殊处理

查找算法优化：

  1. 二分搜索：O(log n)的键值定位效率
  2. 范围判断：确定目标键值所属的子节点
  3. 指针返回：直接返回目标子节点的页面ID
  4. 缓存加速：热点键值的查找结果缓存

插入算法优化：

  1. 查找位置：确定新键值和子指针的插入点
  2. 数组调整：有序数组的插入操作维护排序
  3. 指针关联：建立键值与子节点的正确关联
  4. 分裂检查：节点满载时的分裂触发条件
  5. 递归传播：向上层传播插入导致的分裂

删除算法优化：

  4. 合并检查：节点过少时的合并触发条件

WHY层 - 设计意图： 内部节点是 B+ 树的“路标”。它们不存储实际数据，只存储键（Keys）和子节点指针（Child IDs）。 通过维持多路平衡结构，内部节点保证了树的高度始终处于对数级（O(log N)）， 从而确保即便在海量数据下，任何点查询的 I/O 次数也是稳定且极少的。

WHAT层 - 功能说明： 维护 n 个键和 n+1 个子节点指针的映射关系。 提供快速路由（FindChildPageId），定位给定键应进入哪个子页面。 支持垂直分裂（Split）和合并（Merge）操作，维护树的平衡性。 实现内部结构的二进制序列化（SerializeToPage）。

HOW层 - 实现机制：

  1. 范围映射：内部节点遵循 child[i] < key[i] <= child[i+1] 的逻辑。
  2. 二分查找：FindChildPageId 使用 std::lower_bound 在有序的 keys_ 向量中搜索，减少 CPU 开销。
  3. 动态扩展：Split 时将中间键（Middle Key）向上推送到父节点，实现树的向上生长。
  4. 内存布局：序列化时，键长度、键内容和子 ID 紧凑存储，最大限度利用 8KB 页面空间。
