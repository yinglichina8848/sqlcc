112class BPlusTreeIndex {
113public:
114 // WHY: 在多线程数据库环境中，B+树作为共享数据结构，必须保证并发访问的正确性和高效性。
115 // WHAT: 本`BPlusTreeIndex`类的并发控制策略是委托给底层的`StorageEngine`和更高层的`TransactionManager`来管理。
116 // `BPlusTreeIndex`本身不直接持有细粒度锁，而是依赖于外部组件提供的页面级锁或事务级锁。
117 // HOW:
118 // 1. **页面级并发控制**: 当`BPlusTreeIndex`通过`StorageEngine`读取或写入页面时，`StorageEngine`负责获取和释放页面锁（例如，读写锁）。
119 // 这确保了对单个页面的并发访问是安全的。
120 // 2. **树结构并发控制**: 对于修改B+树结构的操作（如节点分裂、合并），为了维护树的平衡和一致性，
121 // 可能需要更高级别的锁（如锁路径锁存，Latch Coupling，也称为Crabbing Lock）。
122 // 然而，在本`BPlusTreeIndex`的公共接口中，这些锁的获取和释放逻辑预期由调用方（例如`TransactionManager`）
123 // 或更深层次的辅助方法来管理。`BPlusTreeIndex`的私有递归操作方法会隐含地假定页面锁已被适当持有。
124 // 3. **ACID保证**: 事务的隔离性和原子性最终由`TransactionManager`通过两阶段锁（2PL）或MVCC（多版本并发控制）
125 // 等机制来保证。B+树索引作为事务管理的一部分，其操作必须与这些机制协调。
