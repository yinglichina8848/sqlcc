# 数据完整性约束设计（v1.2.2）

## 概述

本文档基于当前 `src/storage_engine/data_integrity_validator.cpp` 的实现，描述 v1.2.2 中数据完整性约束验证器（DataIntegrityValidator）模块的设计、核心组件、运行时配置、已知限制与后续改进建议。

## 模块目标
- 在写入/更新路径对常见的完整性约束（NOT NULL / UNIQUE / FOREIGN KEY / CHECK / DEFAULT）做校验与处理。
- 提供可配置、可扩展的验证策略（Basic / Strict / Enterprise）。
- 提供运行时统计与性能友好的批量验证接口。

## 核心组件

- `CheckConstraintParser`
  - 作用：解析并执行 CHECK 表达式（简化解析器，支持比较、逻辑运算及部分函数如`LEN()`、`ISNULL()`）。
  - 实现要点：语法简单验证（括号/字符串匹配）、基于正则的比较解析、返回 `std::function<bool(const vector<string>&)>` 验证器。
  - 限制：目前表达式解析为简化形式，列定位假设较弱（通常使用记录中第一个值），需在未来加强对列名到索引的映射与完整 AST 支持。

- `ForeignKeyValidator`
  - 作用：验证外键约束、执行级联更新/删除逻辑。
  - 实现要点：提供 `ValidateForeignKey`、`ExecuteCascadeDelete`、`ExecuteCascadeUpdate` 等接口。
  - 限制：当前实现为简化形式（对被引用表的查验为占位/假定通过），需要集成实际的查询接口以保证引用完整性。

- `UniqueConstraintValidator`
  - 作用：管理内存级唯一索引缓存并验证唯一性。
  - 实现要点：维护 `unique_indexes_` 缓存、支持 `CreateUniqueIndex`/`DropUniqueIndex`/`HasUniqueIndex`、`ValidateUniqueConstraint` 支持基于缓存的检测与 `UpdateUniqueValueCache`。
  - 限制：当前缓存模型为内存聚合，未与持久化索引或存储引擎索引紧耦合；并发与排他检查在分布式/多线程写入场景下需更严格的事务边界保证。

- `DefaultValueHandler`
  - 作用：处理默认值表达式解析与生成（数值、字符串、时间、布尔等）。
  - 实现要点：支持 `CURRENT_TIMESTAMP`、数字/字符串解析、`ApplyDefaultValues` 批量处理。
  - 限制：对复杂表达式或函数默认值支持有限（未来可扩展表达式引擎）。

- `DataIntegrityValidator`
  - 作用：面向表级管理完整性约束，提供单条与批量验证接口并维护统计信息。
  - 实现要点：
    - 配置驱动：`IntegrityValidationConfig`（`strict_mode`、各类检查开关、缓存大小等）。
    - 验证流程：逐项执行 NOT NULL → UNIQUE → FOREIGN KEY → CHECK（可按配置短路）。
    - 统计信息：`IntegrityStats`（总校验数、违规计数、平均耗时等）。
    - 工厂函数：`DataIntegrityValidatorFactory::CreateBasic/Strict/Enterprise` 提供不同默认行为。
  - 接口：`ValidateConstraints`、`ValidateConstraintsBatch`、`AddConstraint`、`RemoveConstraint`、`Enable/DisableConstraint`、`GetTableConstraints` 等。

## 配置（重要字段）
- `IntegrityValidationConfig`（示例字段）
  - `strict_mode`（bool）：遇到违规是否立即以错误终止写入路径。
  - `enable_not_null_checking`, `enable_unique_checking`, `enable_foreign_key_checking`, `enable_check_constraint_checking`（bool）：各类型约束开关。
  - `enable_default_value_setting`（bool）：是否在插入时自动填充默认值。
  - `max_constraint_cache_size`（size_t）：限制内存中缓存的约束数量。

## 运行时行为与并发
- 模块使用局部互斥 (`validator_mutex_` / `stats_mutex_`) 保护内存结构（约束缓存、唯一索引缓存、统计数据）。
- `ValidateConstraints` 为 `const` 方法（内部通过 `stats_mutex_` 保护可变统计），适用于并发调用；但对于跨事务的唯一性检查需依赖上层 `TransactionManager` 来保证一致性（当前仅在 Strict 工厂中注入 `TransactionManager`）。
- 批量校验接口 `ValidateConstraintsBatch` 提供了面向批量写入的优化入口（目前列信息为示例，调用方应传入真实列定义）。

## 已知限制与风险
- CHECK 表达式解析器为简化实现：
  - 现阶段对列名到位置映射弱，复杂表达式与函数支持有限。
  - 建议将解析器替换为基于现有 SQL 解析器输出的 AST 验证器以保证列定位与类型安全。

- FOREIGN KEY 验证为占位实现：需与存储引擎/索引查询整合以执行实际存在性验证及级联操作。

- 唯一性校验依赖内存缓存：在崩溃或多节点场景下需持久化/全局一致性设计（引入锁或基于事务的二阶段提交检查）。

- 默认值与表达式支持有限：复杂默认表达式（例如函数、子查询等）尚不支持。

- 测试覆盖率：当前模块应增加单元与集成测试以覆盖边界场景（并发写入、事务回滚、跨表级联）。

## 与 v1.2.0 文档/实现差异（摘要）
- v1.2.0 文档提出的目标中，v1.2.2 代码实现已经：
  - 补充了 `WALBuffer`/`WALWriter`（见存储模块）和 `Prefetcher`/`LazyWriter` 的集成（影响持久化/性能，非本模块直接实现）。
  - 在数据完整性模块中实现了 `ProcedureVM`/`TriggerManager` 的调用钩子（触发器执行点已在 trigger 管理模块实现）。
  - 增强了默认值处理、唯一索引内存缓存与约束管理 API，增加 `ValidateConstraintsBatch` 与工厂构造多种策略。

## 建议的后续工作（短期优先级）
1. 将 `CheckConstraintParser` 与主 SQL 解析器（AST）集成，基于列名生成正确的列索引映射与类型检查。  
2. 用真实查询替换 `ForeignKeyValidator::ValidateForeignKey` 的占位实现（通过 `StorageEngine`/索引进行存在性检查）。  
3. 将 `UniqueConstraintValidator` 的缓存逻辑与持久化索引结合，或在写路径上引入事务级锁以避免竞态。  
4. 扩展单元与集成测试，覆盖并发写入、回滚与触发器场景。
