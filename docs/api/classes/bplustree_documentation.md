# BPlusTreeIndex 类文档

## 类概述

`BPlusTreeIndex` 是 SQLCC 的核心索引组件，实现了 **B+树（B+ Tree）** 数据结构，为数据库提供高效的索引支持。

## WHY: 为什么选择 B+ 树？

**设计动机**：数据库索引需要支持多种查询模式，B+树是最佳选择：

1. **范围查询**：`SELECT * FROM t WHERE id BETWEEN 1 AND 100`
2. **顺序访问**：`ORDER BY id`
3. **高效更新**：动态插入/删除维持平衡结构

**B+树优势对比**：

| 数据结构 | 范围查询 | 顺序访问 | 磁盘I/O | 复杂度 |
|---------|---------|---------|---------|--------|
| B+树 | O(log N + K) | 高效 | 优化 | O(log N) |
| B树 | O(log N + K) | 中等 | 一般 | O(log N) |
| 哈希表 | 不支持 | 不支持 | 差 | O(1) |

**B+树特性**：
- 叶子节点串联，支持高效范围查询和顺序遍历
- 所有数据都在叶子节点，内部节点只存键，减少树高度
- 磁盘I/O优化：节点大小适配页面大小
- 高度平衡，保证查询性能稳定且可预测

**性能特点**：
- 查找复杂度：O(log_m N) - m为阶数，N为记录数
- 范围查询：O(log_m N + K) - K为结果集大小
- 插入/删除：O(log_m N) - 包含可能的节点分裂/合并

## WHAT: 核心功能

### 索引操作
- **创建索引**：`Create()` - 建立新的B+树索引
- **删除索引**：`Drop()` - 移除索引及数据结构
- **插入键值**：`Insert()` - 向索引中插入键值对
- **删除键值**：`Remove()` - 从索引中删除键值对
- **精确查找**：`Search()` - 根据键值查找记录
- **范围查询**：`RangeSearch()` - 查找指定范围内的键

### 辅助功能
- **获取根节点**：`GetRootPageId()` - 获取根页面ID
- **索引统计**：`GetStatistics()` - 返回索引统计信息

## HOW: 实现机制

### 树结构设计

```
        [内部节点]
       /    |    \
   [叶子] [叶子] [叶子]
     ↓      ↓      ↓
   ... →  键→记录 →  ...  (叶子节点双向链表)
```

**节点类型**：
- **根节点**：树的入口点，可为叶子或内部节点
- **内部节点**：只存储键值和子节点指针
- **叶子节点**：存储完整的键值对和双向链表指针

**节点操作**：
- **分裂**：节点溢出时自动分裂并调整父节点
- **合并**：节点下溢时与兄弟节点合并

### 磁盘存储策略

- **页面对齐**：节点大小与磁盘页面大小匹配
- **延迟写入**：批量写入减少I/O操作
- **预读优化**：根据访问模式预读相邻页面

### 并发控制机制

- **读写锁分离**：读操作不阻塞其他读操作
- **乐观并发**：基于版本号的冲突检测
- **死锁避免**：固定的锁获取顺序

## 使用示例

```cpp
#include "storage_engine/b_plus_tree.h"

// 创建索引实例
auto storage_engine = std::make_shared<StorageEngine>(config_manager);
BPlusTreeIndex index(storage_engine, "users", "email");

// 创建索引
if (index.Create()) {
    std::cout << "索引创建成功" << std::endl;
}

// 插入键值
index.Insert("john@example.com", 100);  // 邮箱 -> 页面ID

// 精确查找
auto page_id = index.Search("john@example.com");

// 范围查询
auto range_results = index.RangeSearch("a@example.com", "z@example.com");

// 删除索引
index.Drop();
```

## 设计模式

**组合模式 + 模板方法模式**：
- 树节点作为组件，支持递归组合
- 统一的操作接口，屏蔽内部差异
- 定义操作的通用框架，子类实现具体节点操作

## 性能优化建议

1. **节点大小**：与页面大小匹配（通常4KB/8KB）
2. **缓存策略**：热点数据预加载到内存
3. **批量操作**：减少单次操作的开销
4. **索引选择**：基于查询模式选择索引列
