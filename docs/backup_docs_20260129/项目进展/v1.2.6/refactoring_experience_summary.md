## 🔧 核心技术经验总结

### 1. 头文件路径管理最佳实践
**问题模式**: 源码中直接使用相对路径引用头文件
```cpp
// ❌ 错误示例
#include "ast_nodes.h"  // 相对路径，容易出错

// ✅ 正确示例
#include "sql_parser/ast_nodes.h"  // 完整包路径
```

**解决方案**: 统一使用完整包路径，确保编译器能正确找到头文件。

### 2. 依赖声明的精确性
**问题模式**: 编译时发现缺失的头文件依赖
```bazel
# ❌ 缺失依赖
deps = [
    "//include/sql_parser:ast_node",
    # 缺少 "//include/storage:table_storage"
]

# ✅ 完整依赖
deps = [
    "//include/sql_parser:recursive_query",
    "//include/sql_parser:ast_node",
    "//include/sql_parser:ast_nodes",
    "//include/storage:table_storage",  # 添加缺失依赖
]
```

**解决方案**: 分析编译错误，精确添加对应的Bazel依赖声明。

### 3. 编译选项配置的重要性
**问题模式**: 头文件搜索路径不正确
```bazel
# ❌ 缺少编译选项
cc_library(
    name = "recursive_query",
    srcs = ["recursive_query.cpp"],
    # 缺少 copts 配置
)

# ✅ 正确配置
cc_library(
    name = "recursive_query",
    srcs = ["recursive_query.cpp"],
    copts = [
        "-Iinclude",  # 添加头文件搜索路径
    ],
    # ... 其他配置
)
```

**解决方案**: 正确配置编译器选项，确保头文件能被正确找到。

### 4. 分层修复策略的有效性
**策略核心**: 从底向上，层层验证
```
Layer 1 (基础设施) ← Layer 2 (数据结构) ← Layer 3 (存储层) ← ...
     ✅                        🔄                     🔄
```

**优势**:
- 建立稳定的基础
- 逐层验证修复效果
- 降低复杂度和风险
