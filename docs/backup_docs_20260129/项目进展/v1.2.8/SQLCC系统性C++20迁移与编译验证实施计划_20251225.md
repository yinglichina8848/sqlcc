## 🔧 系统性修复策略详解

### 策略一: 依赖关系修复 (Dependency Fix)

#### 1.1 聚合目标补全
**问题**: 多个包缺少聚合目标，导致外部引用失败

**修复方案**:
```bazel
# 在各模块BUILD.bazel中添加聚合目标
cc_library(
    name = "module_name",  # 聚合目标
    deps = [
        ":sub_target1",
        ":sub_target2",
        ":sub_target3",
    ],
    visibility = ["//visibility:public"],
)
```

**实施范围**:
- `src/procedure/BUILD.bazel` - 添加procedure聚合目标 ✅
- `src/core/BUILD.bazel` - 添加core聚合目标
- `src/sql_parser/BUILD.bazel` - 添加sql_parser聚合目标
- `src/storage_engine/BUILD.bazel` - 添加storage_engine聚合目标
- `src/execution/BUILD.bazel` - 添加execution聚合目标

#### 1.2 循环依赖消除
**问题**: 部分模块存在循环依赖关系

**修复方案**:
```bazel
# 通过接口分离消除循环依赖
cc_library(
    name = "module_interface",
    hdrs = ["interface.h"],
    visibility = ["//visibility:public"],
)

cc_library(
    name = "module_impl",
    srcs = ["impl.cpp"],
    deps = [":module_interface"],
    visibility = ["//visibility:private"],
)
```

### 策略二: 标签格式统一 (Label Normalization)

#### 2.1 引用格式标准化
**问题**: 项目中存在多种不一致的标签引用格式

**修复方案**:
```bazel
# 统一格式规范
# 包内文件: 相对路径
hdrs = ["include/module/header.h"]

# 跨包引用: 完整标签
deps = ["//src/other_module:target"]

# 避免使用: //include/module:header.h (错误)
```

#### 2.2 自动化修复脚本
```bash
#!/bin/bash
# fix_label_formats.sh
echo "统一Bazel标签格式..."

# 修复错误格式
find . -name "BUILD.bazel" -exec sed -i 's|//include/|include/|g' {} \;
find . -name "BUILD.bazel" -exec sed -i 's|//src/|src/|g' {} \;

# 验证格式一致性
echo "格式修复完成，正在验证..."
bazel query //... --output=build 2>&1 | grep -E "(ERROR|WARNING)" || echo "格式验证通过"
```

```bazelrc

build:cpp20 --cxxopt=-stdlib=libc++

build:cpp20 --action_env=CC=clang-18
```

## 📞 风险评估与应对策略

### 技术风险
1. **编译器兼容性**: Clang++-18可能有特定问题
   - 应对: 准备降级方案，使用GCC兼容模式

2. **性能影响**: C++20可能引入性能开销
   - 应对: 进行详细的性能基准测试

3. **依赖库支持**: 第三方库可能不支持C++20
   - 应对: 评估并更新关键依赖库

### 项目风险
1. **时间延误**: 迁移过程可能超出预期
   - 应对: 分阶段执行，及时调整计划

2. **质量下降**: 迁移过程中可能引入缺陷
   - 应对: 加强测试验证，建立回滚机制

3. **团队学习**: 团队需要适应新标准
   - 应对: 提供培训和指导，建立知识库
