## 🔍 编译错误详细分析

### 问题类型一: 依赖目标不存在

#### 现象描述
```
ERROR: /home/liying/sqlcc/tests/unit/basic/BUILD.bazel:51:8: no such target '//src/procedure:procedure': target 'procedure' not declared in package 'src/procedure'
```

#### 根本原因分析
1. **包结构不匹配**: `src/procedure/BUILD.bazel`中定义的是三个独立的目标：
   - `procedure_parser`
   - `procedure_vm`
   - `procedure_trigger_executor`

2. **聚合目标缺失**: 没有定义名为`procedure`的聚合库目标

3. **依赖声明错误**: 测试文件错误地引用了不存在的目标

#### 影响范围
- **影响测试**: `data_types_test`等需要procedure功能的测试
- **影响程度**: 高 - 导致相关测试完全无法编译
- **连锁反应**: 可能影响其他依赖procedure模块的组件

#### 修正方案
```bazel
# 修改前 (错误)
deps = [
    "//src/procedure:procedure",  # 不存在的目标
]

# 修改后 (正确)
deps = [
    "//src/procedure:procedure_parser",
    "//src/procedure:procedure_vm",
    "//src/procedure:procedure_trigger_executor",
]
```

### 问题类型二: 标签引用格式不一致

#### 现象描述
```bazel
# 错误格式
hdrs = ["//include/utils:logger.h"]

# 正确格式
hdrs = ["include/utils/logger.h"]
```

#### 根本原因分析
1. **Bazel标签语法混淆**: 使用了内部包引用语法`//package:target`来引用头文件
2. **相对路径误用**: 应该使用相对路径引用包内文件
3. **配置不统一**: 项目中存在多种不一致的引用格式

#### 影响范围
- **影响目标**: 所有cc_library和cc_test目标
- **影响程度**: 中 - 不影响编译但降低可维护性
- **潜在风险**: 可能导致跨包引用错误

#### 修正方案
```bazel
# 统一使用相对路径格式
hdrs = ["include/utils/logger.h"]  # 相对于WORKSPACE根目录

# 或使用正确的标签格式 (跨包引用时)
hdrs = ["//include/utils:logger.h"]  # 包内文件不应使用此格式
```

### 问题类型三: 环境资源限制

#### 现象描述
```
Command executed.
Output:
== data_types_test ===
(01:04:52) INFO: Invocation ID: xxx
(01:04:52) INFO: Current date is 2025-12-25
(01:04:52) Loading: 0 packages loaded
Command execution timed out after 30 seconds.
```

#### 根本原因分析
1. **系统资源不足**: 编译大型测试时内存/CPU资源不够
2. **依赖链过长**: 测试依赖大量模块导致编译图复杂
3. **缓存机制缺失**: 没有有效利用Bazel缓存
4. **并行度设置不当**: 默认并行编译数可能过高

#### 影响范围
- **影响测试**: 大型集成测试和复杂单元测试
- **影响程度**: 高 - 导致测试验证无法完成
- **时间成本**: 严重影响开发效率

#### 修正方案
```bash
# 优化Bazel配置
export BAZEL_BUILD_OPTS="--jobs=2 --ram_utilization_factor=0.5"

# 分阶段编译
bazel build //src:core  # 先编译核心库
bazel build //src:logger
bazel test //tests/unit/basic:logger_basic_test  # 再测试

# 增加超时时间
bazel test --test_timeout=300 ...
```

### Phase 3: 质量保证 (低优先级)

#### 3.1 自动化检查
```python
# bazel_dependency_checker.py
import os
import re

def check_bazel_files():
    """检查所有BUILD.bazel文件的依赖关系"""
    errors = []

    for root, dirs, files in os.walk('.'):
        if 'BUILD.bazel' in files:
            filepath = os.path.join(root, 'BUILD.bazel')
            with open(filepath, 'r') as f:
                content = f.read()

            # 检查依赖格式
            if re.search(r'//src/[^:]*"', content):
                errors.append(f"Invalid dep format in {filepath}")

    return errors
```

## 📋 具体修正步骤

### 步骤1: 修复procedure依赖问题
```bash
cd /home/liying/sqlcc

# 1. 在src/procedure/BUILD.bazel中添加聚合目标
echo 'cc_library(
    name = "procedure",
    deps = [
        ":procedure_parser",
        ":procedure_vm",
        ":procedure_trigger_executor",
    ],
    visibility = ["//visibility:public"],
)' >> src/procedure/BUILD.bazel

# 2. 恢复原始依赖声明
sed -i 's|//src/procedure:procedure_parser||g' tests/unit/basic/BUILD.bazel
sed -i 's|//src/procedure:procedure_vm||g' tests/unit/basic/BUILD.bazel
sed -i 's|//src/procedure:procedure_trigger_executor||g' tests/unit/basic/BUILD.bazel
echo '        "//src/procedure:procedure",' >> tests/unit/basic/BUILD.bazel
```

### 步骤2: 统一标签格式
```bash
# 创建修复脚本
cat > fix_bazel_labels.sh << 'EOF'
#!/bin/bash
echo "Fixing Bazel label formats..."

# 修复头文件引用
find . -name "BUILD.bazel" -exec sed -i 's|//include/utils|include/utils|g' {} \;
find . -name "BUILD.bazel" -exec sed -i 's|//include/storage|include/storage|g' {} \;
find . -name "BUILD.bazel" -exec sed -i 's|//include/network|include/network|g' {} \;

# 修复源文件引用 (保持相对路径)
find . -name "BUILD.bazel" -exec sed -i 's|//src/|src/|g' {} \;

echo "Label format fix completed."
EOF

chmod +x fix_bazel_labels.sh
./fix_bazel_labels.sh
```

## 🎯 总结与建议

### 核心问题识别
1. **依赖关系混乱**: 聚合目标缺失导致引用错误
2. **标签格式不统一**: 混用不同引用格式降低可维护性
3. **环境资源不足**: 影响大型测试验证
4. **缺少自动化检查**: 无法预防配置错误

### 修正策略建议
1. **优先修复依赖问题**: 添加缺失的聚合目标
2. **统一配置格式**: 建立并执行标签格式规范
3. **优化构建环境**: 调整资源配置和并行策略
4. **建立质量保障**: 实施自动化检查和预防机制

### 实施建议
- **分阶段执行**: 按优先级逐步修复问题
- **充分测试**: 每个修复后进行验证
- **文档更新**: 同步更新相关文档
