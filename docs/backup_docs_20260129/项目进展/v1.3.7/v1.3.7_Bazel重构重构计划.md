# SQLCC v1.3.7 Bazel重构计划

## 项目概述

根据深度分析结果，SQLCC当前的BUILD体系存在严重问题：
- 头文件和源码分离导致复杂的include路径管理
- BUILD配置中存在大量跨包includes hack
- 测试依赖关系不明确
- CMake配置与Bazel体系冲突

本重构目标：
1. 将头文件和源码合并到同一组件目录下
2. 简化BUILD配置，按Bazel最佳实践组织
3. 清除所有CMake配置
4. 实现清晰的模块边界和依赖关系

## 重构原则

1. **一个Bazel package = 一个组件目录**
2. **头文件和源码同目录存放**
3. **BUILD文件定义完整的cc_library目标**
4. **明确deps依赖，不使用全局includes**
5. **测试通过deps引用库目标**

## 重构路线图

### 阶段1: 核心组件重构 (高优先级)
1. **storage_engine/** - 存储引擎是核心组件
2. **sql_parser/** - SQL解析器
3. **sql_executor/** - SQL执行器
4. **core/** - 核心服务

### 阶段2: 基础设施组件
1. **utils/** - 工具类
2. **exception/** - 异常处理
3. **logger/** - 日志系统
4. **config_manager/** - 配置管理器

### 阶段3: 业务组件
1. **execution/** - 执行引擎
2. **transaction/** - 事务管理
3. **network/** - 网络通信
4. **security/** - 安全模块

### 阶段4: 高级功能
1. **procedure/** - 存储过程
2. **trigger/** - 触发器
3. **monitoring/** - 监控系统

### 阶段5: 测试系统更新
1. 更新所有测试BUILD文件
2. 验证依赖关系正确性
3. 清理CMake残留配置

## 预期收益

1. **简化构建**: 移除复杂的include路径管理
2. **提高可靠性**: Bazel能正确验证依赖关系
3. **便于维护**: 模块边界清晰，易于理解
4. **CI友好**: 并行构建和缓存更有效
5. **开发效率**: 减少构建错误和调试时间

## 风险控制

1. **增量重构**: 逐个组件进行，避免大爆炸
2. **自动化验证**: 使用脚本验证构建和测试
3. **备份机制**: 保留git历史，可随时回滚
4. **测试先行**: 确保重构不破坏功能
