# SQLCC循环依赖修复任务清单 v1.2.10

## 问题分析

**核心问题**: Token ↔ AST Node循环依赖导致整个测试系统编译失败

**根本原因**:
1. `ast_node.h` 包含 `#include "sql_parser/token.h"`
2. `token.cpp` 包含 `#include "sql_parser/ast_node.h"`
3. `BinaryExpression` 类直接使用 `Token::Type` 类型

**影响范围**:
- 所有第一层测试编译失败
- 所有依赖SQL解析器的测试无法运行
- 整个测试系统无法正常工作

## 修复策略

### 策略1: 前向声明 + 类型别名 (推荐)
- 在 `ast_node.h` 中使用前向声明 `enum class TokenType : int;`
- 定义独立的TokenType枚举，避免直接依赖Token类
- 在实现文件中包含必要的头文件

### 策略2: 接口抽象层 (长期方案)
- 创建IToken接口抽象Token功能
- AST节点通过接口访问Token
- 完全解耦Token和AST的关系

```cpp
// ast_node.h (问题代码)
#include "sql_parser/token.h"  // 导致循环依赖

public:
  BinaryExpression(std::unique_ptr<Expression> left,
                   std::unique_ptr<Expression> right,
                   Token::Type op);  // 直接使用Token::Type
};
```

```cpp

#include "sql_parser/ast_node.h"  // 反向依赖
```

### 修复后代码结构

```cpp

class BinaryExpression : public Expression {

                   std::unique_ptr<Expression> right,
                   TokenType op);  // 使用独立类型
};
```
