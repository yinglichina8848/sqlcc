# SQLCC v1.1.3 内存安全改进计划

## Phase 2.4.1: 基于审计结果制定详细重构计划

### 问题分类与优先级

根据内存审计报告发现的669个问题，我们将问题分为以下几类并确定优先级：

#### 高优先级问题 (立即处理)

1. **文件描述符直接使用** (约33个问题)
   - 位置: `include/network/mysql_protocol.h`, `include/network/network.h`
   - 风险: 资源泄漏、安全漏洞
   - 解决方案: 创建RAII封装类

2. **成员变量中的裸指针** (约200个问题)
   - 位置: 各核心组件的类成员变量
   - 风险: 析构函数遗漏、内存泄漏
   - 解决方案: 使用智能指针替换

#### 中优先级问题 (第二阶段处理)

1. **函数参数中的裸指针** (约400个问题)
   - 位置: 各执行器、解析器函数
   - 风险: 所有权不明确、潜在悬垂指针
   - 解决方案: 使用引用或智能指针

2. **直接使用new/delete** (约36个问题)
   - 位置: 各源文件中的动态内存分配
   - 风险: 异常安全、内存泄漏
   - 解决方案: 使用std::make_unique/make_shared

### 重构策略

#### 阶段1: 创建基础设施

1. **创建文件描述符RAII封装类**
   - 设计FileDescriptor类，自动管理文件描述符生命周期
   - 支持socket、pipe等常见文件描述符类型
   - 提供移动语义和禁用拷贝

2. **创建智能指针辅助工具**
   - 定义常用的智能指针类型别名
   - 创建make_unique/make_shared的包装函数
   - 提供转换函数，便于现有代码迁移

#### 阶段2: 核心组件重构

1. **网络模块重构**
   - 使用FileDescriptor类替换所有裸文件描述符
   - 使用智能指针管理网络连接对象

2. **存储模块重构**
   - 使用智能指针管理页面和缓冲区
   - 重构B+树实现，使用智能指针管理节点

3. **执行器模块重构**
   - 使用智能指针管理执行计划节点
   - 重构查询执行上下文管理

#### 阶段3: 全面应用

1. **解析器模块重构**
   - 使用智能指针管理AST节点
   - 优化语法树构建和销毁过程

2. **工具模块重构**
   - 重构命令行工具中的内存管理
   - 优化测试工具中的资源使用

### 风险评估与缓解

#### 风险1: 性能影响
- **风险**: 智能指针可能带来轻微性能开销
- **缓解**: 进行性能基准测试，优化热点路径

#### 风险2: 兼容性问题
- **风险**: 接口变更可能影响现有代码
- **缓解**: 保持向后兼容的适配层，逐步迁移

#### 风险3: 引入新bug
- **风险**: 大规模重构可能引入新问题
- **缓解**: 分阶段重构，每阶段充分测试

### 成功标准

1. 所有文件描述符使用RAII管理
2. 所有成员变量使用智能指针
3. 所有函数参数使用引用或智能指针
4. 所有动态内存分配使用make_unique/make_shared
5. 通过所有现有测试用例
6. 内存泄漏检测工具报告零泄漏
7. 性能不低于重构前的95%
