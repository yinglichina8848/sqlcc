## 一、第一层：整体认知

### 1.1 SQLCC 是什么？

**SQLCC**: SQL Cloud-native Cluster  
**中文**: 云原生数据库集群（教学版实现）

**定位**: 
- 教学目的的轻量级关系型数据库
- 帮助学习者理解数据库内部原理
- 实现了现代数据库的核心技术

**一句话概括**:
> SQLCC 是一个可以运行 SQL 语句的数据库系统，就像 MySQL、PostgreSQL 一样，但代码更简单、更容易学习。

### 1.2 SQLCC 能做什么？

| 功能 | 示例 |
|------|------|
| 创建数据库 | `CREATE DATABASE mydb;` |
| 创建表 | `CREATE TABLE users (id INT, name TEXT);` |
| 插入数据 | `INSERT INTO users VALUES (1, 'Alice');` |
| 查询数据 | `SELECT * FROM users WHERE id = 1;` |
| 更新数据 | `UPDATE users SET name = 'Bob' WHERE id = 1;` |
| 删除数据 | `DELETE FROM users WHERE id = 1;` |
| 事务控制 | `BEGIN; ... COMMIT;` |

## 二、第二层：分层架构

### 2.1 为什么需要分层？

**生活例子：餐厅**

```
顾客 → 服务员 → 厨师 → 食材仓库
    ↓        ↓        ↓
   点单    做饭     拿菜
```

**好处**:
- 每层只做自己的工作
- 修改一层不影响其他层
- 便于测试和维护

### 2.2 SQLCC 分层架构

```
┌─────────────────────────────────────────────────────────────────┐
│                      1. 客户端层                                  │
│   - isql 交互式客户端                                            │
│   - API 客户端 (未来)                                            │
│   - 网络协议处理                                                  │
└─────────────────────────────┬───────────────────────────────────┘
                              │ TCP/IP 网络请求
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                      2. 服务器层                                  │
│   - 网络处理：接收和发送网络请求                                   │
│   - 协议解析：理解客户端协议                                       │
│   - 请求路由：将请求分发给正确的处理模块                            │
│   - 会话管理：管理客户端连接状态                                    │
└─────────────────────────────┬───────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                      3. 核心引擎层                                 │
│                                                                 │
│   3.1 SQL 解析器 (SQL Parser)                                    │
│       职责：将 SQL 文本转换为内部结构                              │
│       输入：SELECT * FROM users WHERE id = 1                     │
│       输出：抽象语法树 (AST)                                      │
│                                                                 │
│   3.2 SQL 执行器 (SQL Executor)                                  │
│       职责：根据 AST 执行数据库操作                                │
│       输入：AST                                                  │
│       输出：查询结果                                              │
│                                                                 │
│   3.3 事务管理器 (Transaction Manager)                           │
│       职责：保证事务的 ACID 特性                                  │
│       功能：BEGIN, COMMIT, ROLLBACK                              │
│                                                                 │
│   3.4 配置管理器 (Config Manager)                                │
│       职责：管理系统配置参数                                       │
└─────────────────────────────┬───────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                      4. 存储层                                    │
│                                                                 │
│   4.1 存储引擎 (Storage Engine)                                  │
│       职责：管理数据的物理存储                                     │

│                                                                 │

│       职责：读写磁盘文件                                           │
│                                                                 │

│       职责：加速数据查找                                           │

│                                                                 │
│   4.5 WAL 日志 (Write-Ahead Log)                                 │
│       职责：记录所有修改操作，用于恢复                              │
└─────────────────────────────┬───────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                      5. 基础设施层                                 │
│   - 操作系统 API                                                 │
│   - 文件系统                                                     │

```

### 2.3 每层职责说明

| 层次 | 名称 | 职责 | 例子 |
|------|------|------|------|
| **L1** | 客户端层 | 与用户交互 | isql 客户端 |
| **L2** | 服务器层 | 网络通信 | 接收请求，返回结果 |
| **L3** | 核心引擎层 | 业务逻辑 | 解析 SQL，执行查询 |
| **L4** | 存储层 | 数据管理 | 读写磁盘，缓存数据 |
| **L5** | 基础设施层 | 底层支持 | 操作系统，硬件 |

## 三、第三层：核心模块

### 3.1 SQL 解析器 (SQL Parser)

**What**: 把人类能看懂的 SQL 转换成计算机能理解的结构  
**Why**: 计算机需要知道你要做什么操作  
**How**: 分两步：词法分析 + 语法分析

**工作流程**:
```
SQL 语句: SELECT name FROM users WHERE id = 1
                ↓
         ┌────────────────┐
         │  1. 词法分析   │  把句子拆成单词
         │   (Lexer)     │
         └────────────────┘
                ↓
         Token 序列: [SELECT, name, FROM, users, WHERE, id, =, 1]
                ↓
         ┌────────────────┐
         │  2. 语法分析   │  检查语法是否正确
         │   (Parser)    │  构建语法树
         └────────────────┘
                ↓
         AST (抽象语法树):
                    SELECT
                   /    \
                name    FROM
                       /    \
                    users   WHERE
                           /    \
                          id    =
                               |
                              1
```

**支持的功能**:
- ✅ CREATE/ALTER/DROP DATABASE
- ✅ CREATE/ALTER/DROP TABLE
- ✅ INSERT/UPDATE/DELETE
- ✅ SELECT (支持 WHERE, JOIN, GROUP BY, ORDER BY)
- ✅ GRANT/REVOKE
- ✅ BEGIN/COMMIT/ROLLBACK

**相关文档**:
- `docs/design/sql_parser/sql_parser_design.md` (详细设计)
- `docs/design/sql_parser/SQL语法规则BNF.md` (语法规则)

### 3.2 SQL 执行器 (SQL Executor)

**What**: 根据解析结果执行实际的数据库操作  
**Why**: 光知道做什么不够，还要真的做  
**How**: 根据 AST 类型，调用相应的执行函数

**执行流程**:
```
AST (抽象语法树)
        ↓
   ┌─────────────────────────────────────┐
   │  判断语句类型                         │
   └─────────────────────────────────────┘
        ↓
   ┌──────────┬──────────┬──────────┬──────────┐
   │ SELECT   │  INSERT  │  UPDATE  │  DELETE  │
   │  执行查询 │  执行插入 │  执行更新 │  执行删除 │
   └──────────┴──────────┴──────────┴──────────┘
        ↓
   ┌─────────────────────────────────────┐
   │           调用存储引擎                │
   └─────────────────────────────────────┘
        ↓
   返回结果给客户端
```

**相关文档**:
- `docs/design/sql_executor/sql_executor_design.md` (详细设计)

### 3.3 存储引擎 (Storage Engine)

**What**: 负责数据的物理存储和读取  
**Why**: 数据要持久化保存，不能只存在内存里  
**How**: 使用页式存储 + 缓冲池 + 索引

**核心概念**:
1. **页面 (Page)**: 数据库存储的基本单位，固定 8KB
2. **缓冲池 (Buffer Pool)**: 内存中的缓存，减少磁盘 IO
3. **B+ 树索引**: 加速数据查找

**存储结构**:
```
磁盘文件 (data.db)
┌─────────────────────────────────────────────────┐
│  Page 1: 数据库头信息                             │
│  Page 2: 表 A 的元数据                           │
│  Page 3-100: 表 A 的数据页                        │
│  Page 101-200: 表 B 的数据页                      │
│  ...                                             │
└─────────────────────────────────────────────────┘
```

**内存结构 (缓冲池)**:
```
缓冲池 (内存)
┌─────────────────────────────────────────────────┐
│  ┌─────────┐  ┌─────────┐  ┌─────────┐         │
│  │ Page 3  │  │ Page 5  │  │ Page 10 │ ...    │
│  │ (数据)  │  │ (数据)  │  │ (数据)  │         │
│  └─────────┘  └─────────┘  └─────────┘         │
│      ↑           ↑           ↑                  │
│   最近使用    最近使用     最久未使用            │
│   (LRU 头部)              (LRU 尾部)           │
└─────────────────────────────────────────────────┘
```

**相关文档**:
- `docs/design/storage_engine/storage_engine_overview.md` (概述)
- `docs/design/storage_engine/storage_engine_design.md` (详细设计)

### 3.4 事务管理器 (Transaction Manager)

**What**: 保证数据库操作的正确性  
**Why**: 防止数据不一致，比如转账时钱扣了但没到账  
**How**: 实现 ACID 特性

**ACID 特性**:

| 特性 | 含义 | 实现方式 |
|------|------|---------|
| **A - 原子性** | 要么全做，要么全不做 | WAL (预写日志) |
| **C - 一致性** | 操作前后数据库都处于有效状态 | 约束验证 |
| **I - 隔离性** | 并发操作互不干扰 | MVCC, 2PL |
| **D - 持久性** | 提交的数据不会丢失 | WAL + 磁盘同步 |

**事务示例**:
```sql
-- 转账：从 A 账户转 100 元到 B 账户
BEGIN;                    -- 开启事务
UPDATE accounts SET balance = balance - 100 WHERE id = 'A';
UPDATE accounts SET balance = balance + 100 WHERE id = 'B';
COMMIT;                   -- 提交事务 (两条都成功)
```

**相关文档**:
- `docs/design/transaction_system_design.md` (详细设计)

```
                    ┌─────────────────┐
                    │   SQL 客户端     │

                             ↓
           ┌────────────────┼────────────────┐
           ↓                ↓                ↓
   ┌───────────────┐ ┌───────────────┐ ┌───────────────┐
   │  事务管理器    │ │   存储引擎    │ │  配置管理器    │
   │ (ACID 保证)  │ │ (数据存储)   │ │ (参数管理)   │

           ↓                ↓                ↓

   └─────────────────────────────────────────────────┘
```

### 4.2 典型交互流程

**场景：执行 SELECT 语句**

```
1. 客户端发送: SELECT * FROM users WHERE id = 1
2. 服务器层接收请求
3. SQL 解析器:
   - 词法分析: [SELECT, *, FROM, users, WHERE, id, =, 1]
   - 语法分析: 构建 AST
4. SQL 执行器:
   - 分析 AST 类型 (SELECT)
   - 调用存储引擎读取数据
5. 存储引擎:
   - 检查缓冲池是否有数据
   - 如果没有，从磁盘读取
   - 返回数据
6. SQL 执行器:
   - 格式化结果
7. 服务器层:
   - 发送结果给客户端
8. 客户端显示结果
```

## 附录：常见问题

### Q1: 什么是 AST？

**AST** (Abstract Syntax Tree，抽象语法树) 是 SQL 语句的结构化表示。

```
SQL: SELECT name FROM users WHERE id = 1

AST:
       SELECT
      /    \
    name   FROM
          /    \
       users  WHERE
             /    \
            id    =
                 |
                1
```

### Q2: 什么是缓冲池？

**缓冲池**是内存中的一块区域，用于缓存常用的数据页，减少磁盘 IO。

### Q3: 什么是 WAL？

**WAL** (Write-Ahead Log，预写日志) 是一种日志机制，先写日志再写数据，保证原子性。

### Q4: 什么是 B+ 树？

**B+ 树**是一种平衡树结构，用于索引数据库，加速数据查找。
