 *

 * - 查找复杂度：O(log_m N)
 * - 范围查询：O(log_m N + K)

##### 2. 核心算法注释
```cpp
/**
 * WHAT: Insert - B+树插入操作
 *
 * 插入键值对到B+树索引中，维护树的平衡性。
 * 如果节点溢出，会触发分裂操作。
 *
 * HOW: 递归插入算法
 * 1. 从根节点开始，递归查找插入位置
 * 2. 在叶子节点找到插入点，插入键值对
 * 3. 如果叶子节点溢出（超过最大键数），执行分裂：
 *    - 创建新叶子节点
 *    - 将键值对平均分配到两个节点
 *    - 在父节点插入中间键和新节点指针
 * 4. 如果父节点也溢出，递归向上分裂
 * 5. 如果根节点分裂，树高度增加
 */
bool Insert(const std::string& key, int32_t page_id, size_t offset);
```

##### 3. 分裂算法注释
```cpp
/**
 * WHAT: 分裂操作 - 维护B+树平衡的关键机制
 *
 * 当节点键数超过最大值时，将节点分裂为两个节点。
 * 这保证了树的高度平衡，维持查找性能。
 *
 * HOW: 分裂策略
 * 1. 计算中间位置：(order + 1) / 2
 * 2. 创建新节点，移动一半键值到新节点
 * 3. 对于内部节点：中间键上移到父节点
 * 4. 对于叶子节点：中间键保留在左节点，新节点从中间键开始
 * 5. 更新兄弟节点指针（叶子节点链表）
 */

/**
 * WHY: 为什么需要分片缓冲池而不是单锁设计？
 *
 * 传统缓冲池使用单一互斥锁保护所有操作，导致高并发场景下的锁竞争激烈。
 * 分片设计通过以下方式解决性能瓶颈：
 *
 * 设计原理：
 * 1. 将缓冲池分为16个独立分片
 * 2. 每个分片有独立的锁和LRU队列
 * 3. 使用page_id % 16进行分片定位
 * 4. 减少锁粒度，提高并发性能
 *
 * 性能提升：
 * - 并发读操作：几乎无锁竞争
 * - 写操作：锁竞争减少到1/16
 * - 内存局部性：相邻页面倾向于同一分片
 * - 扩展性：可通过增加分片数进一步提升性能
 *
 * 权衡考虑：
 * - 内存开销：增加分片管理 overhead
 * - 复杂性：并发控制逻辑更复杂
 * - 适用场景：高并发读写负载
 */
class BufferPoolSharded {
```

##### 2. 分片策略注释
```cpp
/**
 * WHAT: GetShardIndex - 页面分片定位算法
 *
 * 将页面ID映射到对应的分片索引，实现负载均衡。
 *
 * HOW: 哈希分片策略
 * 1. 使用page_id % num_shards进行映射
 * 2. 当num_shards为2的幂时，可优化为位运算
 * 3. 保证相邻页面有聚集性，提高缓存命中率
 *
 * 优点：
 * - 计算简单，开销极低
 * - 分布均匀，无热点分片
 * - 局部性好，相邻页面在同一分片
 */

```

##### 3. LRU替换算法注释
```cpp
/**
 * WHAT: ReplacePage - LRU页面替换策略
 *
 * 当缓冲池满时，选择最久未使用的页面进行替换。
 * LRU算法保证最近访问的页面保留在内存中。
 *
 * HOW: 双链表 + 哈希表实现
 * 1. 使用std::list存储页面访问顺序
 * 2. 使用unordered_map记录页面在链表中的位置
 * 3. 访问页面时移到链表头部
 * 4. 需要替换时移除链表尾部页面
 *
 * 优化考虑：
 * - O(1)时间复杂度的访问和更新
 * - 内存开销可控（每个页面8字节指针）
 * - 线程安全：分片锁保护
 */
int32_t ReplacePage(Shard& shard);
```
