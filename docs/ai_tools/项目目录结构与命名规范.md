## 目录命名规范

### 命名原则

1. **小写字母**: 所有目录名使用小写字母
2. **下划线分隔**: 多个单词使用下划线 `_` 分隔
3. **语义清晰**: 目录名应清晰表达其用途
4. **避免缩写**: 除非是广泛认可的缩写（如api, sql, cpp）
5. **一致性**: 同类目录使用一致的命名风格

## 文件命名规范

### C++源文件

#### 命名规则

1. **小写字母**: 全部使用小写字母
2. **下划线分隔**: 多个单词使用下划线 `_` 分隔
3. **语义清晰**: 文件名应清晰表达其内容
4. **对应关系**: 头文件和源文件使用相同的基名

#### 示例

```
database_manager.h          # 数据库管理器头文件
database_manager.cc         # 数据库管理器实现文件
sql_parser.h                # SQL解析器头文件
sql_parser.cc               # SQL解析器实现文件
b_plus_tree.h               # B+树头文件
```

#### 特殊文件

```
main.cc                     # 主程序入口
test_xxx.cc                 # 测试文件
mock_xxx.cc                 # Mock文件
```

1. **中文文档**: 使用中文命名，清晰表达主题

3. **版本文档**: 包含版本号信息
4. **报告文档**: 包含日期或类型信息

## 版本管理与发布规范

### 版本号规范

采用语义化版本控制（Semantic Versioning）：

```
vX.Y.Z

X: 主版本号（不兼容的API修改）
Y: 次版本号（向下兼容的功能性新增）
Z: 修订号（向下兼容的问题修正）
```

#### 示例

```
v1.3.8    # 主版本1，次版本3，修订8
v2.0.0    # 主版本升级，不兼容的API修改
v1.4.0    # 次版本升级，新功能
v1.3.9    # 修订升级，bug修复
```

### 分支管理规范

```
main       # 主分支，稳定版本
develop    # 开发分支，日常开发
feature/*  # 功能分支
hotfix/*   # 热修复分支
release/*  # 发布分支
```

### 发布流程

1. **开发阶段**: 在 `develop` 分支开发
2. **功能完成**: 创建 `feature/*` 分支
3. **测试通过**: 合并到 `develop`
4. **发布准备**: 创建 `release/vX.Y.Z` 分支
5. **发布版本**: 合并到 `main`，打标签 `vX.Y.Z`
