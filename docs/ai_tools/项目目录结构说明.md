## 🎯 各目录职责详解

### 1. 源代码目录 (src/)

#### 架构层次
```
src/
├── core/                  # 核心基础组件
│   ├── config_manager.cpp    # 配置管理器
│   ├── error_handler.cpp     # 错误处理
│   └── database_manager.cpp  # 数据库管理器
├── storage_engine/        # 存储引擎核心
│   ├── buffer_pool*.cpp      # 缓冲池实现
│   ├── disk_manager.cpp      # 磁盘管理
│   ├── b_plus_tree.cpp       # B+树索引
│   └── table_storage.cpp     # 表存储
├── sql_parser/            # SQL解析器
│   ├── lexer_new.cpp         # 词法分析器
│   ├── parser_new.cpp        # 语法分析器
│   └── token_new.cpp         # Token管理
├── execution/             # 执行引擎
│   ├── unified_executor.cpp  # 统一执行器
│   ├── sql_executor.cpp      # SQL执行器
│   └── execution_context.cpp # 执行上下文
├── network/               # 网络通信
│   ├── server_network.cpp    # 服务器网络
│   ├── connection_handler.cpp # 连接处理器
│   └── network.cpp           # 网络工具
├── transaction_manager/   # 事务管理
│   ├── transaction.cpp       # 事务实现
│   └── wal_manager.cpp       # WAL日志
├── isql_network/          # ISQL客户端
│   └── client_main.cpp       # 客户端主程序
└── BUILD.bazel            # Bazel构建配置
```

#### 模块职责说明
- **core/**: 提供基础服务，如配置管理、错误处理、数据库生命周期管理
- **storage_engine/**: 核心存储功能，包括缓冲池、索引、磁盘I/O
- **sql_parser/**: SQL解析功能，将SQL文本转换为AST
- **execution/**: SQL执行逻辑，包含查询优化和结果处理
- **network/**: 网络通信协议，实现客户端-服务器通信
- **transaction_manager/**: 事务ACID保证，WAL日志管理
- **isql_network/**: 命令行客户端，提供交互式SQL界面

### 2. 头文件目录 (include/)

#### 结构映射
```
include/
├── core/                  # 与src/core/对应
├── storage/               # 与src/storage_engine/对应
├── sql_parser/            # 与src/sql_parser/对应
├── execution/             # 与src/execution/对应
├── network/               # 与src/network/对应
├── transaction_manager/   # 与src/transaction_manager/对应
└── utils/                 # 通用工具头文件
```

#### 接口设计原则
- **前向声明**: 头文件中使用前向声明减少编译依赖
- **PIMPL模式**: 复杂类使用PIMPL隐藏实现细节
- **智能指针**: 接口使用智能指针管理资源生命周期
- **抽象接口**: 定义抽象基类便于扩展和测试

## 🔗 目录间依赖关系

### 编译依赖层次
```
存储引擎 (storage_engine/)
    ↑
SQL解析器 (sql_parser/) → 执行引擎 (execution/)
    ↑                           ↑
网络层 (network/) ←———————————————
    ↑
事务管理 (transaction_manager/)
    ↑
核心组件 (core/)
```

### 运行时依赖关系
```
客户端 (isql_network/)
    ↓
网络协议 (network/)
    ↓
SQL执行器 (execution/)
    ↓
存储引擎 (storage_engine/)
    ↓
操作系统I/O
```

## 🎯 AI开发建议

### 理解项目结构的关键点
1. **分层架构**: 从网络层到存储层的清晰层次结构
2. **模块职责**: 每个目录都有明确的单一职责
3. **依赖方向**: 依赖关系从上层到底层的单向流动
4. **接口抽象**: 广泛使用抽象接口便于扩展

### 修改代码的注意事项
1. **构建配置**: 修改代码后需要更新对应的BUILD.bazel
2. **头文件同步**: src/和include/的接口需要保持同步
3. **测试更新**: 修改功能后需要更新相关测试用例
4. **文档同步**: 重要变更需要更新相关文档

### 调试和测试要点
1. **单元测试**: 优先使用模块内的单元测试
2. **集成测试**: 验证模块间协作的集成测试
3. **端到端测试**: 使用test_basic_sql.sh验证完整流程
4. **性能测试**: 使用专门的性能测试工具
