## 🔍 结构差异分析

### 1. 全局头文件分析
**需要保留在include/的全局头文件**:
- `sqlcc_pch.h` - 项目全局预编译头文件
- `storage_engine_pch.h` - 存储引擎预编译头文件
- 其他全局接口头文件

**迁移策略**: 这些全局头文件保持在include/根目录下

### 2. 组件头文件分析
**已完成合并的组件**:
- `storage_engine/` - 部分头文件已在src/storage_engine/下
- `network/` - 部分头文件已在src/network/下

**需要迁移的组件**:
- `core/` - include/core/ → src/core/
- `utils/` - include/utils/ → src/utils/
- `exception/` - include/exception/ → src/exception/
- `execution/` - include/execution/ → src/execution/
- `sql_parser/` - include/sql_parser/ → src/sql_parser/
- `sql_executor/` - include/sql_executor/ → src/sql_executor/
- `transaction/` - include/transaction/ → src/transaction/
- `storage/` - include/storage/ → src/storage_engine/
- `types/` - include/types/ → src/types/
- 其他组件...

### 3. 特殊情况分析
**重复文件处理**:
- 部分头文件在include/和src/下都存在，需要对比确定最新版本
- 废弃文件处理：`_deprecated_storage_headers/`目录可以清理

**构建文件处理**:
- `include/BUILD.bazel`需要更新为只包含全局头文件
- 各组件的BUILD.bazel需要从组件目录下引用头文件

## ⚠️ 风险识别与应对

### 技术风险
1. **编译错误**: 逐个组件验证，及时修复
2. **依赖关系混乱**: 使用bazel query工具分析
3. **头文件冲突**: 对比文件内容，选择最新版本

### 实施风险
1. **迁移脚本错误**: 先手动迁移核心组件，再自动化
2. **回滚困难**: 保留git历史，支持快速回滚
3. **时间评估不足**: 分阶段实施，弹性调整
