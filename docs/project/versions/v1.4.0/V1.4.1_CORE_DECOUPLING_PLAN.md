## 3. 执行阶段与任务分解

### 阶段 A：接口抽象 (P0)

**A1. IStorageEngine 接口**
- 目标：新增接口头文件并可编译
- 产出：`src/storage_engine/storage_engine_interface.h`
- 验收：
  - `bazel build //src/storage_engine:storage_engine_interface`
  - `rg -n "virtual.*= 0;"` 期望 ≥ 10

**A2. Core 关键接口**
- 目标：抽取 `IUserContext`, `ITransactionContext`
- 产出：`src/core/user_context.h`, `src/core/transaction_context.h`
- 验收：
  - `bazel build //src/core:core_interface`
  - `rg -n "virtual.*= 0;" src/core/user_context.h src/core/transaction_context.h` ≥ 8

### 阶段 B：依赖解耦 (P0)

**B1. 移除 Core ↔ Execution 循环依赖**
- 目标：BUILD 依赖断环
- 验收：
  - `bazel query "allpaths(//src/core:core, //src/execution:execution)"` 为空
  - `bazel build //src/core:core`
  - `bazel build //src/execution:execution`

**B2. Core 不引用 Storage 实现**
- 目标：Core 依赖接口而非实现
- 验收：
  - `rg -n "buffer_pool_sharded|table_storage" src/core` 期望无输出
  - `rg -n "IStorageEngine" src/core/core_database_manager.h` 期望有输出

### 阶段 C：编译基线 (P0)

**C1. 基线构建**
- 目标：核心模块编译通过
- 验收：
  - `bazel build //src/core:core`
  - `bazel build //src/execution:execution`
  - `bazel build //src/storage_engine:storage_engine`

**C2. 基线测试 (最小集)**
- 目标：基础测试通过
- 验收：
  - `bazel test //tests/level1_foundation/... --test_output=errors`

## 4. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 接口抽象不完整 | 编译失败 | 逐文件增量替换，确保可回退 |
| BUILD 依赖断环影响执行模块 | 扩散改动 | 限制影响范围，仅改必要依赖 |
| 文档与现状偏差 | 评审失败 | 设计文档标注“现状/规划” |

- Core/Execution/Storage 编译通过
- Level1 基础测试通过
