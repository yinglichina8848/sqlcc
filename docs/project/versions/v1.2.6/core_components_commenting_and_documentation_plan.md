## 教育性设计原则

### 学生学习导向
**核心原则**: 每个核心组件和关键算法都必须保证学生仅通过阅读源码注释就能理解其设计理念、功能特性和实现机制。

#### 理念理解验证
- **Why层深入**: 不仅仅说明"为什么这么做"，还要解释背后的理论基础和实际需求
- **What层完整**: 不仅描述功能，还要说明解决了什么问题，带来了什么优势
- **How层透彻**: 不仅解释实现，还要说明为什么选择这种实现方式

#### 设计理念自包含
- **分片缓冲池**: 学生应能从注释理解为什么需要分片、分片如何工作、为什么16分片
- **B+树索引**: 学生应能理解B+树为什么适合磁盘存储、叶子链表如何支持范围查询
- **并发控制**: 学生应能明白锁策略的选择依据和性能权衡

#### 学习路径引导
- **渐进式理解**: 从概念到实现，从简单到复杂
- **关联性建立**: 通过注释引用建立组件间的关联关系
- **实践指导**: 注释中包含关键设计决策的思考过程

### 文档补充策略
**原则**: 对每个核心组件和关键类或者关键算法，进行文档补充说明，保证源码注释外的独立文档支持。

#### 组件文档清单
- **BufferPoolSharded**: 分片缓冲池设计详解文档
- **BPlusTreeIndex**: B+树索引设计详解文档
- **WAL系统**: 预写日志系统设计详解文档
- **SQL Parser**: 递归下降解析器设计详解文档
- **Query Optimizer**: 查询优化器设计详解文档
- **Transaction Manager**: 事务管理器设计详解文档
- **Lock Manager**: 锁管理器设计详解文档

#### 关键算法文档
- **LRU缓存策略**: 页面替换算法详解
- **哈希分片算法**: 分片策略和负载均衡
- **B+树分裂合并**: 平衡维护算法
- **两阶段锁协议**: 并发控制机制
- **死锁检测算法**: 资源管理策略

#### 文档编写标准
- **独立性**: 文档应能独立阅读，不依赖其他文档
- **完整性**: 涵盖Why/What/How三个层面
- **实例化**: 包含具体代码示例和运行时图示
- **对比性**: 说明与其他方案的优缺点比较

### 质量标准

#### 优秀注释的标准 ✅
- **准确性**：注释必须准确反映代码实际功能和行为
- **深度分析**：不仅说明What，还要解释Why（设计决策）和How（技术实现）
- **上下文提供**：说明代码的使用场景和依赖关系
- **意图阐明**：帮助理解设计者的思维过程和权衡考虑
- **技术细节**：包含重要的技术实现细节和性能考虑

#### 注释覆盖要求
- **类和结构体**：100% 详细注释（Why层 + What层 + How层）
- **关键函数**：100% 完整注释（尤其是public接口）
- **复杂算法**：100% 算法逻辑注释
- **重要变量**：80%+ 关键变量和数据结构注释
- **边界条件**：100% 异常处理和边界情况注释
