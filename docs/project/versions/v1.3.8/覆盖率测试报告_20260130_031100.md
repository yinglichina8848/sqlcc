## 📝 BUILD.bazel 配置修复

### 修复策略

采用标准化配置，为所有测试添加：

```bazel
copts = [
    "-g",       # 调试信息
    "-Wall",    # 所有警告
    "-Wextra",  # 额外警告
],
tags = [
    "coverage",  # 覆盖率测试标签
    "levelX",    # 层级标签
    "unit",      # 单元测试标签
],
testonly = True,  # 仅用于测试
```

### 修复示例

**文件**: `tests/level1_foundation/basic/BUILD.bazel`

**修复前**:
```bazel
cc_test(
    name = "basic_test",
    srcs = ["basic_test.cpp"],
    deps = [
        "//src/exception:exception",
        "@com_google_googletest//:gtest_main",
        "@com_google_googletest//:gtest",
    ],
    tags = ["coverage", "level1"],
)
```

**修复后**:
```bazel
cc_test(
    name = "basic_test",
    srcs = ["basic_test.cpp"],
    copts = [
        "-g",
        "-Wall",
        "-Wextra",
    ],
    deps = [
        "//src/exception:exception",
        "@com_google_googletest//:gtest_main",
        "@com_google_googletest//:gtest",
    ],
    tags = ["coverage", "level1", "unit"],
    testonly = True,
)
```

## 🔍 问题分析

### 发现的问题

1. **BUILD.bazel配置不统一**
   - 部分测试缺少标准copts配置
   - 部分测试缺少标准tags配置
   - 部分测试缺少testonly标志

2. **自动化脚本局限性**
   - 自动化修复脚本难以处理所有格式的BUILD.bazel文件
   - 需要手动审核和修复复杂的配置文件

3. **覆盖率数据收集**
   - 需要确保所有BUILD.bazel文件配置正确
   - 需要验证覆盖率工具链的配置

### 解决方案

1. **手动修复BUILD.bazel文件**
   - 逐个检查和修复BUILD.bazel文件
   - 确保配置符合规范要求

2. **建立配置审查机制**
   - 在提交前检查BUILD.bazel配置
   - 使用bazel query验证配置正确性

3. **完善自动化工具**
   - 改进自动化修复脚本
