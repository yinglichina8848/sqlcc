# Bazel错误知识库

## 常见错误类型及解决方案

### 1. 标签引用错误 (Label Reference Errors)

#### 错误模式
```
Label '//include:core/execution_context.h' is invalid because 'include/core' is a subpackage; perhaps you meant to put the colon here: '//include/core:execution_context.h'?
```

#### 原因
Bazel标签引用格式错误，子包路径中缺少冒号分隔符。

#### 解决方案
- 错误格式: `//package/subpackage:target`
- 正确格式: `//package/subpackage:target`

#### 示例修复
```bazel
# 错误
hdrs = ["//include:core/execution_context.h"]

# 正确
hdrs = ["//include/core:execution_context"]
```

### 2. Glob模式错误 (Glob Pattern Errors)

#### 错误模式
```
Error in glob: glob pattern '!window_function_node.cpp' didn't match anything, but allow_empty is set to False
```

#### 原因
glob模式匹配不到文件，但未设置`allow_empty = True`。

#### 解决方案
- 添加`allow_empty = True`参数
- 或者移除不存在的文件模式

#### 示例修复
```bazel
# 错误
srcs = glob([
    "*.cpp",
    "!nonexistent_file.cpp",  # 文件不存在
])

# 正确 - 方案1: 添加allow_empty
srcs = glob([
    "*.cpp",
    "!nonexistent_file.cpp",
], allow_empty = True)

# 正确 - 方案2: 移除不存在的文件
srcs = glob([
    "*.cpp",
])
```

### 3. 目标未声明错误 (Target Not Declared)

#### 错误模式
```
target 'sqlcc_parser' not declared in package 'src/sql_parser'
```

#### 原因
BUILD文件中缺少目标定义，或者目标名称拼写错误。

#### 解决方案
- 检查BUILD文件中的目标名称
- 确保目标正确定义
- 使用`bazel query`验证目标存在

#### 示例检查
```bash
# 检查包中的所有目标
bazel query "//src/sql_parser:*"

# 检查目标是否存在
bazel query "//src/sql_parser:sqlcc_parser"
```

### 4. 缺失依赖错误 (Missing Dependencies)

#### 错误模式
```
missing dependency declaration
```

#### 原因
目标使用了其他库的功能，但未在deps中声明依赖。

#### 解决方案
- 添加缺失的依赖到deps列表
- 检查头文件包含关系
- 使用`bazel query "deps(//target)"`分析依赖

### 5. 循环依赖错误 (Circular Dependencies)

#### 错误模式
```
Circular dependency detected
```

#### 原因
包之间存在循环依赖关系。

#### 解决方案
- 重构代码以打破循环依赖
- 使用接口分离或依赖注入
- 创建中介层来解耦组件

#### 检测方法
```bash
# 检查循环依赖
bazel query "somepath(//target1, //target2)"
```

### 6. 编译选项错误 (Compilation Flag Errors)

#### 错误模式
```
unknown warning option
```

#### 原因
编译选项与编译器版本不兼容。

#### 解决方案
- 检查编译器版本
- 更新.bazelrc中的编译选项
- 使用条件编译选项

### 7. 模块导入错误 (Module Import Errors)

#### 错误模式
```
module not found
```

#### 原因
C++20模块导入路径错误或模块未正确构建。

#### 解决方案
- 检查模块文件路径
- 确保模块目标正确声明
- 使用`--experimental_enable_bzlmod`标志

## 调试工具使用指南

### bazel_debug.sh
```bash
# 构建并分析错误
./tools/bazel_debug.sh //:sqlcc

# 显示依赖关系
./tools/bazel_debug.sh --deps //:sqlcc

# 查询依赖
./tools/bazel_debug.sh --query "deps(//:sqlcc)"
```

### bazel_check_deps.sh
```bash
# 检查循环依赖
./tools/bazel_check_deps.sh --circular //:sqlcc

# 检查缺失依赖
./tools/bazel_check_deps.sh --missing //src/...

# 生成依赖图
./tools/bazel_check_deps.sh --graph --format=dot //:sqlcc
```

### bazel_fixer.sh
```bash
# 自动修复所有问题
./tools/bazel_fixer.sh --auto-fix

# 只修复标签引用
./tools/bazel_fixer.sh --label-fix //:sqlcc

# 只修复glob模式
./tools/bazel_fixer.sh --glob-fix //src/...
```

## 最佳实践

### 1. 标签引用规范
- 总是使用完整路径: `//package/subpackage:target`
- 避免使用相对路径
- 确保子包使用正确的冒号分隔

### 2. Glob模式使用
- 谨慎使用排除模式(`!pattern`)
- 对于可能为空的glob，添加`allow_empty = True`
- 定期清理不再存在的文件引用

### 3. 依赖管理
- 显式声明所有依赖
- 避免过度依赖
- 定期检查循环依赖

### 4. 构建配置
- 使用`.bazelrc`管理构建选项
- 为不同编译器版本提供配置
- 测试构建选项的兼容性

## 常见问题排查步骤

1. **清理缓存**
   ```bash
   bazel clean --expunge
   ```

2. **检查语法**
   ```bash
   ./tools/bazel_fixer.sh --format
   ```

3. **分析依赖**
   ```bash
   ./tools/bazel_check_deps.sh --health //target
   ```

4. **构建调试**
   ```bash
   ./tools/bazel_debug.sh --verbose //target
   ```

5. **查阅文档**
   - 检查Bazel官方文档
   - 查看项目构建指南
   - 搜索常见错误解决方案

## 版本兼容性

### Clang 18 + C++20 支持

#### 已验证功能
- C++20标准特性
- 模块系统 (experimental)
- 概念和约束
- 协程支持
- 范围库

#### 已知限制
- 某些C++20特性在Clang 18中仍为实验性
- 模块系统需要额外配置
- 某些警告选项可能不兼容

#### 配置建议
```bazelrc
# Clang 18 + C++20 配置
build:modern --cxxopt=-std=c++20
build:modern --cxxopt=-stdlib=libc++
build:modern --linkopt=-stdlib=libc++
build:modern --cxxopt=-Wno-error=maybe-uninitialized
build:modern --define=SQLCC_MODERN_CPP=1
build:modern --define=SQLCC_CLANG18_FEATURES=1
```
