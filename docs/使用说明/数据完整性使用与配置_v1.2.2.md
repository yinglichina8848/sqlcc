# 数据完整性使用与配置（v1.2.2）

本文档说明如何在应用中使用 `DataIntegrityValidator`、常用配置示例以及调试/排查建议。

## 快速示例（C++）

1) 创建基础验证器（轻量）

```cpp
#include "storage/data_integrity_validator.h"

auto storage = /* 获取 StorageEngine 实例 */;
auto validator = DataIntegrityValidatorFactory::CreateBasicValidator(storage);

// 在写入前调用
auto result = validator->ValidateConstraints(table_name, column_names, column_types, values);
if (result != CONSTRAINT_VALID) {
    // 处理违规
}
```

2) 严格模式（在写路径作为强校验，失败则回滚）

```cpp
auto txn_manager = /* 获取 TransactionManager */;
auto strict_validator = DataIntegrityValidatorFactory::CreateStrictValidator(storage, txn_manager);

// 严格模式会在工厂中启用 all-checks 和 strict_mode
```

3) Enterprise 模式（自定义配置）

```cpp
IntegrityValidationConfig cfg;
cfg.strict_mode = false;
cfg.enable_not_null_checking = true;
cfg.enable_unique_checking = true;
cfg.enable_foreign_key_checking = true;
cfg.enable_check_constraint_checking = true;
cfg.enable_default_value_setting = true;
cfg.max_constraint_cache_size = 1024;

auto ent_validator = DataIntegrityValidatorFactory::CreateEnterpriseValidator(storage, txn_manager, cfg);
```

## 常用配置建议
- 生产环境：开启 `enable_not_null_checking`、`enable_unique_checking`，并在关键写操作路径采用 `strict_mode`。  
- 对于需要高吞吐的批量加载：可在加载期关闭 `enable_foreign_key_checking`，加载完成后通过后台校验任务做完整性校验并修复。  
- 对于分布式部署：应在上层引入全局一致性机制，避免仅依赖本地内存缓存的唯一性校验。

## 调试与排查
- 查看统计：`GetIntegrityStats()` 返回平均验证时间与违规计数，定位热点表或高频违规类型。  
- CHECK 表达式失败：先在单元测试环境对 `CheckConstraintParser::EvaluateExpression()` 做覆盖测试，确认表达式语法是否被支持。
- 外键失败（占位实现）：若遇到外键不一致问题，请检查触发器/应用逻辑，并尽快升级到支持 StorageEngine 查询的外键验证实现。

## 建议的测试用例
- 单列/复合唯一索引并发插入测试。  
- 外键存在性测试（参考实现需扩展为真实查询）。  
- CHECK 表达式解析边界（引号、括号、函数调用）。  
- 默认值填充与时间戳验证。

## 迁移注意事项
- 升级到 v1.2.2 后，若之前依赖存储引擎索引保证唯一性，请验证 `UniqueConstraintValidator` 与索引的一致性策略。  
- 在开启 `strict_mode` 前，先在预发布环境运行完整校验以捕获历史违规数据。
