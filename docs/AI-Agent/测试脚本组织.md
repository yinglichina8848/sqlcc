# SQLCC 测试脚本组织详解

## 🧪 测试体系架构

SQLCC采用多层次测试策略，确保代码质量和功能正确性。

## 📁 测试文件组织

### 测试脚本层次
```
test*.sh                    # 端到端测试脚本
├── test_basic_sql.sh         # 基础SQL功能测试
├── test_comprehensive_sqlcc.sh # 综合功能测试
├── test_isql_sqlcc.sh        # ISQL客户端测试
└── test_storage_integration.sh # 存储集成测试

test/                      # 单元测试目录
├── *_test.cpp               # 单元测试文件
└── test_data/               # 测试数据

tests/                     # 集成测试目录
├── integration/             # 集成测试
└── performance/             # 性能测试

test_data/                 # 测试数据目录
├── *.sql                    # SQL测试文件
├── *.dat                    # 数据文件
└── expected_outputs/        # 期望输出
```

## 🎯 测试类型说明

### 1. 端到端测试 (E2E)
```bash
# test_basic_sql.sh - 基础功能验证
#!/bin/bash
echo "Testing basic SQL functionality..."

# 启动服务器
./sqlcc --port 18647 &
SERVER_PID=$!

# 等待服务器启动
sleep 2

# 执行SQL测试
echo "SELECT 1;" | nc localhost 18647

# 清理
kill $SERVER_PID
```

### 2. 单元测试 (Unit Tests)
```cpp
// src/storage_engine/buffer_pool_test.cpp
TEST(BufferPoolTest, FetchPage) {
    auto buffer_pool = BufferPoolFactory::Create(BufferPool::Type::STANDARD);

    // 测试页面获取
    auto page = buffer_pool->FetchPage(1);
    EXPECT_NE(page, nullptr);

    // 测试页面内容
    EXPECT_EQ(page->GetPageId(), 1);
}
```

### 3. 集成测试 (Integration Tests)
```cpp
// tests/integration/sql_execution_test.cpp
TEST(SqlExecutionIntegrationTest, FullQueryExecution) {
    // 设置测试数据库
    DatabaseManager db_manager;
    db_manager.CreateDatabase("test_db");

    // 执行完整查询流程
    SqlExecutor executor;
    auto result = executor.Execute("SELECT * FROM test_table");

    // 验证结果
    EXPECT_TRUE(result.first);  // 执行成功
    EXPECT_FALSE(result.second.empty());  // 有返回结果
}
```

## 🔧 测试执行流程

### 自动化测试脚本
```bash
# 运行所有测试
bazel test //...

# 运行特定测试
bazel test //src/storage_engine:buffer_pool_test

# 运行端到端测试
./test_basic_sql.sh

# 生成覆盖率报告
bazel coverage //...
```

### CI/CD集成
```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Build
        run: bazel build //...
      - name: Test
        run: bazel test //...
      - name: Coverage
        run: bazel coverage //...
```

## 📊 测试覆盖率目标

### 覆盖率指标
- **总体目标**: ≥50% 行覆盖率
- **核心模块**: ≥70% 覆盖率
- **网络模块**: ≥60% 覆盖率（当前较低）

### 覆盖率报告分析
```bash
# 生成详细报告

        -o coverage_report/

firefox coverage_report/index.html
```

## 🎯 AI开发测试要点

### 编写测试的原则
1. **测试先行**: 先写测试，再实现功能
2. **单一职责**: 每个测试验证一个具体行为
3. **独立性**: 测试间互不依赖，可任意顺序执行
4. **可重复性**: 测试结果稳定，不受外部因素影响

### 测试文件命名规范
- 单元测试: `component_test.cpp`
- 集成测试: `component_integration_test.cpp`
- 端到端测试: `e2e_test.sh`

### 修改代码时的测试策略
1. **运行相关测试**: 修改代码后运行相关测试
2. **回归测试**: 确保修改不破坏现有功能
3. **新增测试**: 为新功能编写相应测试
4. **覆盖率检查**: 确保测试覆盖新代码
