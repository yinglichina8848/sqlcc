# SQLCC 测试脚本组织详解

## 🧪 测试体系架构

SQLCC采用多层次测试策略，结合自动化测试流水线，确保代码质量和功能正确性。

## 🎯 测试类型说明

### 1. 端到端测试 (E2E)
```bash
# test_basic_sql.sh - 基础功能验证
#!/bin/bash
echo "Testing basic SQL functionality..."

# 启动服务器
./sqlcc --port 18647 &
SERVER_PID=$!

# 等待服务器启动
sleep 2

# 执行SQL测试
echo "SELECT 1;" | nc localhost 18647

# 清理
kill $SERVER_PID
```

### 2. 单元测试 (Unit Tests)
```cpp
// src/storage_engine/buffer_pool_test.cpp
TEST(BufferPoolTest, FetchPage) {
    auto buffer_pool = BufferPoolFactory::Create(BufferPool::Type::STANDARD);

    // 测试页面获取
    auto page = buffer_pool->FetchPage(1);
    EXPECT_NE(page, nullptr);

    // 测试页面内容
    EXPECT_EQ(page->GetPageId(), 1);
}
```

### 3. 集成测试 (Integration Tests)
```cpp
// tests/integration/sql_execution_test.cpp
TEST(SqlExecutionIntegrationTest, FullQueryExecution) {
    // 设置测试数据库
    DatabaseManager db_manager;
    db_manager.CreateDatabase("test_db");

    // 执行完整查询流程
    SqlExecutor executor;
    auto result = executor.Execute("SELECT * FROM test_table");

    // 验证结果
    EXPECT_TRUE(result.first);  // 执行成功
    EXPECT_FALSE(result.second.empty());  // 有返回结果
}
```

## 🔧 测试执行流程

### 自动化测试流水线 ⭐新增

SQLCC v1.1.4 引入了完整的自动化测试流水线，实现了从环境准备到报告生成的端到端自动化。

#### 流水线架构
```
测试流水线执行流程
├── 1. 环境准备 (prepare_test_environment.sh)
├── 2. 构建验证 (validate_build.sh)
├── 3. 单元测试 (run_unit_tests.sh)
├── 4. 集成测试 (run_integration_tests.sh)
├── 5. 通信协议测试 (test_communication_protocol.sh)
├── 6. 端到端测试 (run_e2e_tests.sh)
├── 7. 覆盖率收集 (collect_coverage_data.sh)
└── 8. 报告生成 (generate_test_report.sh)
```

#### 流水线使用方法

##### 完整测试执行
```bash
# 执行完整测试流水线
./scripts/test_pipeline.sh

# 查看详细日志
tail -f test_reports/pipeline_report_*.txt
```

##### 自定义执行模式
```bash
# 仅构建验证
BUILD_ONLY=true ./scripts/test_pipeline.sh

# 跳过通信测试
COMMUNICATION_TEST=false ./scripts/test_pipeline.sh

# 仅覆盖率收集
COVERAGE_ENABLED=true ./scripts/test_pipeline.sh

# 快速测试模式
TEST_MODE=quick ./scripts/test_pipeline.sh
```

##### 单独执行步骤
```bash
# 仅环境准备
./scripts/prepare_test_environment.sh

# 仅构建验证
./scripts/validate_build.sh

# 仅单元测试
./scripts/run_unit_tests.sh

# 仅覆盖率分析
./scripts/collect_coverage_data.sh
```

#### 流水线配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `TEST_MODE` | `full` | 测试模式：`full`, `quick`, `smoke` |
| `COVERAGE_ENABLED` | `true` | 是否收集覆盖率数据 |
| `COMMUNICATION_TEST` | `true` | 是否执行通信协议测试 |
| `BUILD_ONLY` | `false` | 是否仅执行构建验证 |

### CI/CD集成

#### GitHub Actions配置
```yaml
# .github/workflows/test-pipeline.yml
name: SQLCC Test Pipeline

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]
  schedule:
    - cron: '0 2 * * *'  # 每天凌晨2点运行完整测试

jobs:
  test-pipeline:
    runs-on: ubuntu-latest

    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: test123
          MYSQL_DATABASE: sqlcc_test
        ports:
          - 3306: 3306

    steps:
    - uses: actions/checkout@v3

    - name: Setup Bazel
      run: |
        curl -fsSL https://bazel.build/bazel-release.pub.gpg | gpg --deimport
        curl -Lo bazel https://github.com/bazelbuild/bazel/releases/download/4.2.1/bazel-4.2.1-linux-x86_64
        chmod +x bazel
        sudo mv bazel /usr/local/bin/

    - name: Run Test Pipeline
      run: ./scripts/test_pipeline.sh
      env:
        TEST_MODE: full
        COVERAGE_ENABLED: true
        COMMUNICATION_TEST: true

    - name: Upload Coverage Reports
      uses: codecov/codecov-action@v3
      with:
        file: ./coverage_report/lcov.info
        flags: automated
        name: codecov-automated

    - name: Upload Test Artifacts
      uses: actions/upload-artifact@v3
      with:
        name: test-results
        path: |
          test_reports/
          coverage_report/

    - name: Coverage Quality Gate
      run: |
        if [ -f "coverage_report/summary.txt" ]; then
          COVERAGE=$(grep "lines......:" coverage_report/summary.txt | sed 's/.*lines......: \([0-9.]*\).*/\1/' | head -1)
          if (( $(echo "$COVERAGE < 11.5" | bc -l 2>/dev/null || echo "1") )); then
            echo "Coverage regression detected: $COVERAGE%"
            exit 1
          fi
        fi
```

## 📊 测试覆盖率目标

### 覆盖率指标
- **总体目标**: ≥50% 行覆盖率
- **核心模块**: ≥70% 覆盖率

## 🎯 AI开发测试要点

### 编写测试的原则
1. **测试先行**: 先写测试，再实现功能
2. **单一职责**: 每个测试验证一个具体行为
3. **独立性**: 测试间互不依赖，可任意顺序执行
4. **可重复性**: 测试结果稳定，不受外部因素影响

### 测试文件命名规范
- 单元测试: `component_test.cpp`
- 集成测试: `component_integration_test.cpp`
- 端到端测试: `e2e_test.sh`

### 修改代码时的测试策略
1. **运行相关测试**: 修改代码后运行相关测试
2. **回归测试**: 确保修改不破坏现有功能
3. **新增测试**: 为新功能编写相应测试
4. **覆盖率检查**: 确保测试覆盖新代码
