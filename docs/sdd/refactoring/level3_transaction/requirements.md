# Level 3 Transaction 重构需求规范

## 1. 概述

### 1.1 功能名称
Level 3 Transaction 模块拆分解耦重构

### 1.2 需求来源
- 来源: Level 2 重构分析报告
- 优先级: P0
- 负责人: AI 开发团队
- 相关需求: REQ-CORE-001, REQ-CORE-002

### 1.3 目标用户
SQLCC 开发团队

### 1.4 背景
基于 Level 2 重构分析，发现 transaction_manager 模块存在以下问题：
- wal_manager.cpp (54.3 KB) 职责过重：WAL写入+日志管理+检查点+恢复
- transaction_manager.cpp (43.9 KB) 事务管理逻辑复杂
- 缺少事务上下文接口抽象

---

## 2. 需求定义 (EARS 格式)

### REQ-TRAN-001: WAL 管理职责分离

| 属性 | 值 |
|------|-----|
| ID | REQ-TRAN-001 |
| 优先级 | P0 |
| 状态 | 草稿 |
| 来源 | Level 2 分析报告 |
| 创建日期 | 2026-02-02 |

#### 描述

**当** WAL 管理模块职责过多导致维护困难时,
**我想要** 将 WAL 管理拆分为多个单一职责组件,
**以便于** 提高代码可维护性和可测试性.

#### 接受标准

- [ ] WAL 写入职责分离到独立 WriteAheadLog 类
- [ ] 日志管理职责分离到 LogManager 类
- [ ] 检查点职责分离到 CheckpointManager 类
- [ ] 恢复职责分离到 RecoveryManager 类
- [ ] 各组件支持独立测试

#### 边界条件

| 条件 | 处理方式 |
|------|---------|
| 多线程并发写入 | 使用分片锁保证线程安全 |
| 检查点期间写入 | 暂停写入或使用双缓冲区 |
| 恢复过程失败 | 回滚到上一个检查点 |

#### 相关需求

| 关系 | ID | 说明 |
|------|-----|------|
| 依赖 | REQ-TRAN-002 | 需要事务上下文接口 |
| 依赖 | REQ-TRAN-003 | 需要恢复机制 |

---

### REQ-TRAN-002: 事务上下文接口抽象

| 属性 | 值 |
|------|-----|
| ID | REQ-TRAN-002 |
| 优先级 | P0 |
| 状态 | 草稿 |
| 来源 | Level 2 分析报告 |

#### 描述

**当** 执行模块需要访问事务状态时,
**我想要** 通过 ITransactionContext 接口访问事务管理功能,
**以便于** 解耦执行模块与事务管理的具体实现.

#### 接受标准

- [ ] 定义 ITransactionContext 接口
- [ ] 提供 TransactionContextImpl 实现
- [ ] 支持事务生命周期管理
- [ ] 支持分布式事务（如果需要）
- [ ] 编译通过，测试通过

#### 边界条件

| 条件 | 处理方式 |
|------|---------|
| 事务不存在 | 抛出异常或返回错误 |
| 事务已结束 | 拒绝重复提交/回滚 |
| 并发访问 | 使用乐观/悲观锁 |

---

### REQ-TRAN-003: 事务管理器职责分离

| 属性 | 值 |
|------|-----|
| ID | REQ-TRAN-003 |
| 优先级 | P1 |
| 状态 | 草稿 |
| 来源 | Level 2 分析报告 |

#### 描述

**当** transaction_manager.cpp 包含过多职责时,
**我想要** 将其拆分为多个单一职责类,
**以便于** 降低模块复杂度，提高可维护性.

#### 接受标准

- [ ] 事务调度职责分离到 TransactionScheduler
- [ ] 事务隔离级别管理分离到 IsolationLevelManager
- [ ] 死锁检测职责保留并优化
- [ ] 事务超时管理职责分离
- [ ] 各职责支持独立配置
