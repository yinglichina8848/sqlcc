# SQLCC v1.1.5 存储过程和触发器重构报告

## 📊 重构概述

### 基本信息
- **版本号**: v1.1.5
- **报告日期**: 2025年12月16日
- **重构目标**: 支持存储过程和触发器功能
- **重构范围**: SQL解析器、执行引擎、存储引擎、权限系统
- **预估工作量**: 6-8个月（分阶段实施）

### 重构背景
当前SQLCC数据库系统在v1.1.5版本中具备了基本的SQL-92支持，但执行引擎仍处于简化状态，无法支持存储过程和触发器等高级数据库特性。添加这些功能需要对核心架构进行重大调整。

## 🎯 重构目标

### 主要目标
1. **实现完整的存储过程支持**
   - CREATE PROCEDURE语法解析和执行
   - 参数传递和返回值处理
   - 存储过程语言（变量、控制流、异常处理）

2. **实现触发器机制**
   - CREATE TRIGGER语法解析
   - 事件监听和自动触发
   - BEFORE/AFTER触发器支持

3. **重构执行引擎架构**
   - 从占位符实现升级为真正的SQL执行引擎
   - 支持复杂查询执行和过程调用
   - 实现执行计划缓存和优化

4. **扩展存储引擎**
   - 添加元数据存储系统
   - 支持存储过程和触发器对象的持久化
   - 扩展索引系统用于元数据查询

## 📋 当前架构分析

### 现有架构优势
- ✅ 模块化设计，职责分离清晰
- ✅ 存储引擎成熟，支持表数据和索引
- ✅ 事务管理器提供ACID保证
- ✅ 权限系统基础架构完备

### 现有架构问题
- ❌ 执行引擎过于简化，无法处理复杂逻辑
- ❌ 缺乏元数据管理系统
- ❌ 没有事件驱动机制
- ❌ SQL解析器不支持过程和触发器语法

## 🔧 详细重构方案

### 1. SQL解析器扩展

#### 当前状态
- 支持基本的DDL/DML/DQL语句
- AST节点类型有限
- 语法分析器功能单一

#### 重构内容
- **新增AST节点类型**：
  - `ProcedureNode`: 存储过程定义
  - `TriggerNode`: 触发器定义
  - `CallNode`: 过程调用语句
  - `BlockNode`: 复合语句块
  - `VariableDeclarationNode`: 变量声明
  - `ControlFlowNode`: 控制流语句

- **语法扩展**：
  ```sql
  CREATE PROCEDURE proc_name(param_list)
  BEGIN
      -- procedure body
  END;

  CREATE TRIGGER trig_name
  BEFORE/AFTER INSERT/UPDATE/DELETE ON table_name
  FOR EACH ROW
  BEGIN
      -- trigger body
  END;
  ```

- **词法分析器增强**：
  - 添加PROCEDURE、TRIGGER、BEGIN、END等关键字
  - 支持过程语言的词法规则

#### 影响范围
- `src/sql_parser/lexer.cpp`: 词法分析器
- `include/sql_parser/ast_nodes.h`: AST节点定义
- `src/sql_parser/ast_nodes.cpp`: AST节点实现
- `src/sql_parser/parser.cpp`: 语法分析器

### 2. 执行引擎重构

#### 当前状态
- `SqlExecutor::Execute()` 仅返回 "EXECUTED: " + sql
- 缺乏真正的执行逻辑
- 无法处理复杂查询

#### 重构内容
- **执行引擎架构重构**：
  ```
  SqlExecutor (高层接口)
  ├── QueryExecutor (查询执行器)
  │   ├── PlanGenerator (计划生成器)
  │   ├── PlanOptimizer (计划优化器)
  │   └── PlanExecutor (计划执行器)
  ├── ProcedureExecutor (过程执行器)
  │   ├── ProcedureManager (过程管理器)
  │   ├── VariableManager (变量管理器)
  │   └── ControlFlowHandler (控制流处理器)
  └── TriggerExecutor (触发器执行器)
      ├── TriggerManager (触发器管理器)
      └── EventDispatcher (事件分发器)
  ```

- **执行上下文管理**：
  - `ExecutionContext`: 执行上下文，包含变量、事务状态等
  - `ScopeManager`: 作用域管理，支持嵌套作用域
  - `CallStack`: 调用栈管理，支持递归调用

- **过程语言支持**：
  - 变量声明和赋值
  - 条件语句（IF-THEN-ELSE）
  - 循环语句（WHILE、FOR）
  - 异常处理（TRY-CATCH）
  - 返回语句（RETURN）

#### 影响范围
- `src/core/sql_executor.cpp`: 重构主执行器
- `include/core/execution_context.h`: 新增执行上下文
- `src/core/procedure_executor.cpp`: 新增过程执行器
- `src/core/trigger_executor.cpp`: 新增触发器执行器

### 3. 存储引擎扩展

#### 当前状态
- 支持表数据和索引存储
- 缺乏元数据存储能力

#### 重构内容
- **元数据存储系统**：
  ```
  系统表:
  - mysql.proc: 存储过程元数据
  - mysql.triggers: 触发器元数据
  - mysql.variables: 会话变量
  ```

- **元数据管理器**：
  - `MetadataManager`: 元数据管理接口
  - `ProcedureMetadata`: 存储过程元数据结构
  - `TriggerMetadata`: 触发器元数据结构

- **持久化存储**：
  - 扩展表存储系统支持系统表
  - 实现元数据的序列化和反序列化
  - 支持元数据的版本控制

#### 影响范围
- `src/storage_engine/metadata_manager.cpp`: 新增元数据管理器
- `include/storage/metadata_manager.h`: 元数据管理接口
- `src/storage_engine/system_tables.cpp`: 系统表实现

### 4. 事务和并发控制扩展

#### 当前状态
- 支持基本的ACID事务
- 缺乏对存储过程事务的特殊处理

#### 重构内容
- **存储过程事务语义**：
  - 支持自治事务（PRAGMA AUTONOMOUS_TRANSACTION）
  - 异常时的回滚处理
  - 保存点管理

- **触发器事务处理**：
  - 触发器在触发事务中执行
  - 支持触发器引发的回滚
  - 级联触发器的死锁预防

#### 影响范围
- `src/core/transaction_manager.cpp`: 扩展事务管理器
- `include/core/transaction_context.h`: 事务上下文增强

### 5. 权限系统扩展

#### 当前状态
- 支持基本的用户和权限管理
- 缺乏对存储过程和触发器的权限控制

#### 重构内容
- **权限对象扩展**：
  - EXECUTE权限：执行存储过程的权限
  - TRIGGER权限：创建触发器的权限
  - ALTER ROUTINE权限：修改存储过程的权限

- **权限验证增强**：
  - DEFINER vs INVOKER安全模型
  - 存储过程的权限继承
  - 触发器的执行权限检查

#### 影响范围
- `src/core/permission_validator.cpp`: 扩展权限验证器
- `include/core/permissions.h`: 权限定义扩展
