## 🔍 **依赖错误分析**

### 1. **错误的子目录标签格式**

在 `src/BUILD.bazel` 中的 `storage_engine` 库定义中，发现了多处错误的子目录文件引用：

```bazel
# ❌ 错误格式 - 引用子目录文件时使用了错误的标签格式
"//src/storage_engine/buffer_pool:lru_manager.cpp",
"//src/storage_engine/table_storage:page_raii.cpp",
```

**问题分析**:
- Bazel中，当文件位于子目录时，应该直接在同一包内引用，而不是创建子包标签
- 正确的格式应该是将文件直接列在主包的 `srcs` 中，而不是通过子包引用

### 2. **头文件路径不一致性**

```bazel
# ❌ 不一致的头文件路径
"//include/storage:b_plus_tree.h",
"//include/storage_engine:b_plus_tree_node.h",
```

**问题分析**:
- 头文件路径应该统一使用 `//include/package:header.h` 格式
- 需要确保所有头文件都位于正确的include目录结构中

### 3. **文件存在性验证缺失**

需要系统性地验证所有在BUILD文件中引用的文件是否实际存在于文件系统中。

## 🎯 **改进方案**

### **第一阶段: 标签格式标准化**

#### 1.1 修复子目录文件引用

**当前错误格式**:
```bazel
srcs = [
    "//src/storage_engine:storage_engine.cpp",
    "//src/storage_engine/buffer_pool:lru_manager.cpp",  # ❌ 错误
    "//src/storage_engine/table_storage:page_raii.cpp",   # ❌ 错误
]
```

**正确格式**:
```bazel
srcs = [
    "storage_engine.cpp",
    "buffer_pool/lru_manager.cpp",        # ✅ 正确 - 相对路径
    "table_storage/page_raii.cpp",        # ✅ 正确 - 相对路径
]
```

#### 1.2 统一头文件路径

**标准化规则**:
- 所有头文件使用 `//include/package:header.h` 格式
- 确保include目录结构与包结构一致

#### 2.2 依赖关系分析

### **步骤3: 自动化修复工具**

增强现有的修复工具：

```python
# enhanced_dependency_fixer.py
import os
import re

def fix_build_file(file_path):
    """修复BUILD文件中的依赖关系错误"""
    with open(file_path, 'r') as f:
        content = f.read()

    # 修复子目录文件引用
    content = re.sub(
        r'"//src/([^/]+):([^/]+/[^"]*)"',
        r'"\2"',
        content
    )

    # 统一头文件路径
    content = re.sub(
        r'"//include/([^:]+):([^"]*)"',
        r'"//include/\1:\2"',
        content
    )

    with open(file_path, 'w') as f:
        f.write(content)

if __name__ == "__main__":
    fix_build_file("src/BUILD.bazel")
```
