# 《SQLCC v1.3.8 头文件迁移与 BUILD 系统重构综合计划》（修正版）

**计划制定时间**: 2026年1月21日
**计划制定者**: AI Assistant（基于架构师审查意见修正）
**计划目标**: 完成头文件从include/到src/的规范化迁移，采用 Bazel 最佳实践重建 BUILD 系统，建立强制性依赖约束

## 📋 计划概述（基于审查意见修正）

### 总体评价与结论
- ✅ **技术方向正确**：分期合理、工程可控
- ⚠️ **尚可控制但需硬约束**：缺少 Bazel 级"硬约束"，需补 3 条强规则
- ✅ **值得立刻执行**：但必须先补规则，否则执行到 Phase 2 会出现结构性回退

### 必须修正的关键问题（已纳入计划）
1. ❌ **include 目标形态错误**：原计划使用 `#include "src/utils/xxx.h"`（Bazel 反模式），修正为 `#include "utils/config_manager.h"`
2. ❌ **includes = ["."] 过渡期管理**：明确 Phase 1 允许，Phase 2 禁止新增，Phase 3 全部删除
3. ❌ **PCH 处理不当**：将 `sqlcc_pch.h`、`storage_engine_pch.h` 降级为 `common_includes.h`，禁止继续使用 pch 概念
4. ❌ **依赖层级缺失**：新增硬性依赖层级红线，禁止反向依赖
5. ❌ **storage/transaction 合并风险低估**：Phase 3 拆分为子阶段，避免 header-only 泄漏

### 背景分析（更新）
当前SQLCC项目存在以下问题：
1. **头文件分散**: 头文件同时存在于include/和src/目录下，造成管理混乱
2. **BUILD系统复杂**: 存在循环依赖和不规范的依赖关系，缺乏 Bazel 最佳实践
3. **编译效率低下**: 复杂的include路径导致编译缓慢，PCH 使用不当
4. **维护困难**: 头文件位置不一致，IDE支持差，依赖关系不清

### 总体目标（强化）
1. **统一头文件位置**: 采用"头文件就地原则"，所有 .h 与对应 .cpp 同目录
2. **重建BUILD系统**: 使用 `strip_include_prefix = ""`，`include_prefix = ""`，消除 `includes = ["."]`
3. **建立依赖约束**: 定义模块层级红线，禁止反向依赖，消除循环依赖
4. **规范化include路径**: 统一使用基于 Bazel target 的虚拟根路径

### 实施原则（强化）
- ✅ **渐进式迁移**: 分阶段进行，避免一次性大改动
- ✅ **可回滚性**: 保留备份，确保出现问题能快速恢复
- ✅ **测试驱动**: 每次迁移后进行充分测试
- ✅ **团队协作**: 分工明确，进度可控
- ✅ **强制规范化**: 建立 Code Review 硬规则，禁止反模式

## 🎯 强制规范化规则（新增）

### 🔺 依赖层级红线（硬约束）
```
utils (基础工具)
  ↓
exception (异常处理)
  ↓
types (类型定义)
  ↓
core (核心服务)
  ↓
execution (执行引擎) ← sql_parser (SQL解析)
  ↓
sql_executor (SQL执行)
  ↓
transaction (事务管理)
  ↓
storage_engine (存储引擎)
  ↓
network (网络通信)
  ↓
bin/app (应用层)
```

**禁止规则**:
- ❌ utils → core（反向依赖）
- ❌ exception → sql_executor（跨层依赖）
- ❌ storage_engine → sql_executor（反向依赖）
- ❌ transaction → execution（反向依赖）

### 🔑 Include 路径规范（唯一合法）
```cpp
// ✅ 正确：基于 Bazel target 的虚拟根
#include "utils/config_manager.h"
#include "core/execution_context.h"
#include "transaction/transaction_manager.h"

// ❌ 禁止：绝对路径或相对路径
#include "src/utils/config_manager.h"
#include "../utils/config_manager.h"
#include <utils/config_manager.h>
```

### 📋 BUILD.bazel 强制模板
```bazel
cc_library(
    name = "component_name",
    srcs = glob(["*.cpp"]),
    hdrs = glob(["*.h"]),
    strip_include_prefix = "",
    include_prefix = "",
    deps = [
        "//src/utils",
        "//src/exception",
        # 严格按照依赖层级声明
    ],
    visibility = ["//src:__subpackages__"],
)
```

### ⚠️ PCH 处理策略（修正）
- 将 `sqlcc_pch.h`、`storage_engine_pch.h` 重命名为 `common_includes.h`
- 降级为普通头文件，不再使用 pch 概念
- 明确 include 在需要的地方
