## 1. 项目背景

SQLCC 项目将采用 **双分支并行开发** 模式：

| 分支 | 负责人 | 技术栈 | 目标 |
|------|--------|--------|------|
| `release/1.x` (C++主线) | OpenClaw | C++20 | 维护、稳定、持续集成 |
| `feature/rust-impl` | 高小药 | Rust | 现代化重构、内存安全 |

## 4. PR 审核流程

### 4.1 提交流程

```
┌─────────────────────────────────────────────────────────────────┐
│                     PR 审核流程                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   开发者完成阶段性开发                                            │
│           │                                                     │
│           ▼                                                     │
│   ┌─────────────┐                                              │
│   │  提交 PR    │                                              │
│   └─────────────┘                                              │
│           │                                                     │
│           ▼                                                     │
│   ┌─────────────┐     ┌─────────────┐                         │
│   │  CI 检查    │────▶│  失败?      │                         │
│   └─────────────┘     └─────────────┘                         │
│           │              │                                     │
│           ▼              ▼                                     │
│   ┌─────────────┐     修复后重新提交                            │
│   │  代码审核   │                                              │
│   └─────────────┘                                              │
│           │                                                     │
│           ▼                                                     │
│   ┌─────────────┐     ┌─────────────┐                         │
│   │  审核通过   │────▶│  合并到主分支│                         │
│   └─────────────┘     └─────────────┘                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 审核要点

| 类别 | 检查项 |
|------|--------|
| **代码质量** | 编译通过、无警告、符合编码规范 |
| **测试** | 单元测试通过、覆盖率达标 |
| **文档** | 必要的注释、API 文档更新 |
| **兼容性** | 接口向后兼容（对于 C++ 分支） |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 分支差异过大 | 合并困难 | 定期同步关键接口定义 |
| Rust 学习曲线 | 进度延迟 | 参考 C++ 实现，先移植后优化 |
| 测试用例不一致 | 对比无效 | 共享测试用例，统一验收标准 |
| 主分支冻结 | 阻塞开发 | 小改动可直接提交，重大变更走 PR |
