# AI开发原则

## 项目目录结构管理原则

### 1. 主目录整洁原则
- **禁止在主目录下执行代码生成、编译和测试运行**
- 所有生存、调试和测试文件必须放置在对应的子目录中
- 主目录仅保留项目核心配置文件、文档和顶层构建定义

### 2. 测试文件组织原则
- 所有调试文件必须放置在 `tests/components/debug/` 目录下
- 所有性能测试文件必须放置在 `tests/performance/` 目录下
- 测试文件必须通过Bazel测试体系进行集成和管理

### 3. Bazel集成原则
- 所有测试必须通过Bazel构建系统进行管理
- 测试文件必须定义在对应的BUILD.bazel配置文件中
- 测试套件必须通过test_suite进行组织和管理

### 4. 文件移动和清理原则
- 定期检查主目录，将生成的测试文件和调试文件移动到对应目录
- 移动文件后必须更新相应的Bazel配置文件
- 确保主目录保持整洁，便于项目维护和管理

## 实施指南

### 新文件创建
- 调试文件：创建在 `tests/components/debug/` 目录
- 性能测试：创建在 `tests/performance/` 目录  
- 单元测试：创建在对应的 `tests/components/` 子目录

### 现有文件整理
- 定期运行文件整理脚本检查主目录
- 将发现的生存和调试文件移动到对应目录
- 更新Bazel配置文件以集成移动的文件

### 构建和测试
- 所有构建和测试操作必须在构建目录中进行
- 使用Bazel命令运行测试：`bazel test //tests/...`
- 禁止在主目录直接编译或运行测试

## 内存安全原则

### 1. 智能指针使用原则

#### 1.1 所有权语义选择
- **std::unique_ptr**: 用于独占所有权的资源管理
  - 文件句柄、套接字、网络连接
  - 动态分配的内存块
  - 不可共享的系统资源

- **std::shared_ptr**: 用于共享所有权的资源管理
  - 缓冲池中的页面对象
  - 缓存的数据结构
  - 需要在多个组件间共享的对象

- **std::weak_ptr**: 用于打破循环引用
  - 观察者模式中的观察者对象
  - 缓存中的弱引用

#### 1.2 智能指针设计模式
```cpp
// 正确：工厂函数返回智能指针
class BufferPool {
public:
  static std::shared_ptr<BufferPool> Create(DiskManager* disk_manager,
                                           size_t pool_size) {
    return std::make_shared<BufferPool>(disk_manager, pool_size);
  }

private:
  BufferPool(DiskManager* disk_manager, size_t pool_size);
  // 私有构造函数，确保只能通过工厂函数创建
};

// 错误：直接暴露裸指针
class BufferPool {
public:
  BufferPool* CreateInstance() { // 不要这样做
    return new BufferPool();
  }
};
```

#### 1.3 智能指针传递准则
- **函数参数**: 优先使用 `const std::shared_ptr<T>&` 或 `std::weak_ptr<T>`
- **返回值**: 总是返回智能指针，避免返回裸指针
- **成员变量**: 使用智能指针存储需要管理生命周期的对象

```cpp
// 推荐写法
void ProcessPage(std::shared_ptr<Page> page) {
  // 处理页面
}

std::shared_ptr<Page> GetPage(int32_t page_id) {
  return page_table_[page_id]; // 返回智能指针
}

// 不推荐写法
void ProcessPage(Page* page) { // 裸指针，调用者需要管理生命周期
  // 处理页面
}

Page* GetPage(int32_t page_id) { // 返回裸指针，调用者负责释放
  return page_table_[page_id].get();
}
```

#### 1.4 避免智能指针滥用
- **局部变量**: 对于生命周期明确的局部对象，使用栈分配
- **性能敏感代码**: 在热点路径上评估智能指针开销
- **循环引用**: 使用 `std::weak_ptr` 打破循环引用

### 2. RAII 资源管理原则

#### 2.1 RAII 封装设计
- **资源获取即初始化**: 在构造函数中获取资源，在析构函数中释放
- **异常安全**: 确保在异常情况下资源正确释放
- **不可复制**: 对于独占资源，使用 `= delete` 要用复制操作

```cpp
class FileDescriptor {
public:
  explicit FileDescriptor(int fd) : fd_(fd) {}
  ~FileDescriptor() {
    if (fd_ >= 0) {
      ::close(fd_);
    }
  }

  // 要用复制，避免双重释放
  FileDescriptor(const FileDescriptor&) = delete;
  FileDescriptor& operator=(const FileDescriptor&) = delete;

  // 支持移动语义
  FileDescriptor(FileDescriptor&& other) noexcept : fd_(other.fd_) {
    other.fd_ = -1;
  }

private:
  int fd_;
};
```

#### 2.2 系统资源封装
- **文件描述符**: 封装 `open()`/`close()` 操作
- **网络套接字**: 封装 `socket()`/`bind()`/`listen()`/`accept()`/`close()`
- **内存映射**: 封装 `mmap()`/`munmap()` 操作
- **互斥锁**: 封装 `pthread_mutex_init()`/`pthread_mutex_destroy()`

#### 2.3 RAII 卫哨模式
```cpp
class MutexGuard {
public:
  explicit MutexGuard(std::mutex& mutex) : mutex_(mutex) {
    mutex_.lock();
  }

  ~MutexGuard() {
    mutex_.unlock();
  }

  // 要用复制
  MutexGuard(const MutexGuard&) = delete;
  MutexGuard& operator=(const MutexGuard&) = delete;

private:
  std::mutex& mutex_;
};

// 使用示例
void ThreadSafeFunction() {
  MutexGuard guard(mutex_); // 自动加锁
  // 执行线程安全操作
  // 函数返回时自动解锁
}
```

### 3. 内存管理最佳实践

#### 3.1 禁止手动内存管理
- **永远不要使用**: `new`/`delete`, `malloc`/`free`
- **例外情况**: 性能极致优化的特定场景，必须有详细注释和审计

#### 3.2 容器使用原则
- **首选标准容器**: `std::vector`, `std::string`, `std::unordered_map`
- **避免裸数组**: 使用 `std::array` 或 `std::vector` 替代 `T[]`
- **智能指针容器**: 使用 `std::vector<std::shared_ptr<T>>` 而非裸指针

#### 3.3 异常安全保证
- **强异常保证**: 操作要么完全成功，要么完全回滚
- **RAII 配合**: 使用 RAII 确保资源在异常情况下正确释放
- **智能指针**: 自动处理异常情况下的内存释放

### 4. 并发安全原则

#### 4.1 锁管理准则
- **最小化锁粒度**: 只在必要时持有锁
- **避免死锁**: 使用固定的锁顺序，或使用 `std::lock()`
- **超时机制**: 为锁操作设置合理的超时时间

```cpp
// 推荐：带超时的锁获取
std::unique_lock<std::timed_mutex> lock(latch_, std::defer_lock);
if (!lock.try_lock_for(std::chrono::milliseconds(5000))) {
  // 超时处理，避免永久阻塞
  return false;
}
```

#### 4.2 数据竞争防护
- **原子操作**: 对共享变量使用 `std::atomic`
- **内存屏障**: 在必要时使用内存屏障确保顺序
- **不可变对象**: 对于只读共享数据，考虑使用不可变对象

### 5. 错误处理原则

#### 5.1 异常使用准则
- **异常层次**: 定义清晰的异常层次结构
- **RAII 配合**: 异常不会阻止资源释放
- **异常安全**: 确保异常不会导致资源泄漏或状态不一致

#### 5.2 错误码 vs 异常
- **异常**: 用于程序错误和不可恢复的情况
- **错误码**: 用于可预期的错误情况
- **混合使用**: 根据具体场景选择合适的错误处理机制

### 6. 性能优化原则

#### 6.1 零开销抽象
- **智能指针**: 在非性能关键路径上使用智能指针
- **RAII**: RAII 封装不应带来运行时开销
- **内联优化**: 对关键函数使用 `inline` 提示

#### 6.2 内存布局优化
- **缓存对齐**: 重要数据结构使用 `alignas` 对齐
- **内存局部性**: 将相关数据放在一起，减少缓存未命中
- **对象池**: 对于频繁分配/释放的小对象，使用对象池

### 7. 代码组织原则

#### 7.1 接口设计
- **Pimpl 模式**: 隐藏实现细节，减少编译依赖
- **工厂模式**: 使用工厂函数创建对象，返回智能指针
- **依赖注入**: 通过构造函数注入依赖，便于测试

#### 7.2 模块化设计
- **单一职责**: 每个类只负责一个明确的功能
- **依赖倒置**: 依赖抽象而非具体实现
- **接口隔离**: 提供最小化的接口，避免不必要的依赖

### 8. 测试原则

#### 8.1 内存安全测试
- **ASan/LSan**: 启用地址/泄漏检测器进行测试
- **Valgrind**: 使用 Valgrind 进行详细的内存检查
- **单元测试**: 为每个 RAII 类编写完整的单元测试

#### 8.2 并发测试
- **线程安全测试**: 测试多线程环境下的正确性
- **死锁检测**: 使用工具检测潜在的死锁情况
- **竞态条件**: 编写测试暴露竞态条件

### 9. 实施指南

#### 9.1 代码审查清单
- [ ] 是否使用了智能指针而非裸指针？
- [ ] 是否正确实现了 RAII 模式？
- [ ] 是否避免了循环引用？
- [ ] 是否正确处理了异常安全？
- [ ] 是否有内存泄漏风险？

#### 9.2 重构步骤
1. **识别问题**: 使用工具检测内存问题
2. **设计方案**: 为每个资源设计 RAII 封装
3. **逐步重构**: 从叶子类开始，逐步向上重构
4. **测试验证**: 每个重构步骤后运行完整测试套件
5. **性能调优**: 监控重构后的性能影响

#### 9.3 工具使用
- **编译器警告**: 启用所有内存相关警告
- **静态分析**: 使用 Clang Static Analyzer
- **动态分析**: 使用 Valgrind, ASan, LSAN
- **代码覆盖**: 确保测试覆盖所有内存管理路径

### 头文件引用原则
- 不要使用 #include "../../../include/xxx.h" ，而是使用 #include "include/xxx.h" 的方式，保持代码的简洁和可维护性。用 -I 参数指定include目录，这样，就可以使用 #include "xxx.h" 的方式引用头文件了。
- 所有的头文件不在源码目录下，在 项目主目录的 include 目录下，记住这个原则进行查找和修改
- 不要随意自行创建头文件，除非进行新部件和类的设计和开发，测试程序所使用的核心代码和头文件都是应当存在的，只是重新整理了目录结构，进行了移动，认真查找，
