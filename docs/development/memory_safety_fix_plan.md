# SQLCC内存安全修复总体规划

## 项目概述
针对v1.2.3版本中识别的内存安全问题进行系统性修复，包括：
- 裸指针替换为智能指针 (157个高风险问题)
- 未初始化指针初始化 (116个中风险问题) 
- 空指针解引用防护 (254个低风险问题)
- RAII模式全面应用 (网络、存储、执行引擎)
- 内存泄漏消除 (重点关注new/delete配对)
- 缓冲区溢出防护 (数组边界检查)

## 修复策略

### 阶段1: 核心组件修复 (高风险)
1. **触发器管理器 (TriggerManager)**
   - 修复 `SqlExecutor* sql_executor_` 裸指针
   - 修复 `const TriggerDefinition*` 返回类型
   - 修复 `const RowData*` 参数传递

2. **网络管理器 (NetworkManager)**
   - 修复全局裸指针 `static ServerNetworkManager* g_server`
   - 修复连接状态中的裸指针

3. **执行引擎 (ExecutionEngine)**
   - 修复执行上下文中的裸指针
   - 修复策略模式中的裸指针

### 阶段2: 存储引擎修复 (中风险)
1. **缓冲区管理器**
   - 修复页面指针管理
   - 修复缓存一致性管理器

2. **B+树索引**
   - 修复节点指针管理
   - 修复迭代器中的裸指针

### 阶段3: SQL解析器修复 (低风险)
1. **AST节点管理**
   - 修复表达式树中的裸指针
   - 修复语句树中的裸指针

2. **词法分析器**
   - 修复输入缓冲区管理

### 阶段4: 工具函数修复
1. **字符串操作**
   - 替换不安全的字符串函数
   - 添加缓冲区边界检查

2. **内存操作**
   - 替换 `memcpy` 为安全的内存操作
   - 添加大小验证

## 修复原则

1. **智能指针优先**: 尽可能使用 `std::unique_ptr` 和 `std::shared_ptr`
2. **RAII模式**: 确保资源的自动生命周期管理
3. **异常安全**: 所有操作都必须异常安全
4. **性能考虑**: 避免不必要的内存分配和拷贝
5. **向后兼容**: 保持API兼容性，必要时提供迁移路径

## 质量目标

- 内存泄漏率: 0%
- 裸指针使用率: <5% (仅限必要场景)
- 智能指针化率: >95%
- 代码覆盖率: >90%
- 性能下降: <5%

## 实施步骤

1. **代码审计**: 完成详细的代码扫描和风险评估
2. **核心修复**: 优先修复高风险组件
3. **测试验证**: 每个修复都必须有完整的测试覆盖
4. **性能测试**: 确保修复不会显著影响性能
5. **文档更新**: 更新相关文档和API说明
6. **迁移支持**: 提供向后兼容的迁移工具

## 风险管控

1. **渐进式修复**: 分阶段进行，避免大规模一次性修改
2. **回滚机制**: 每个修复都要有回滚方案
3. **兼容性测试**: 确保与现有代码的兼容性
4. **性能监控**: 实时监控修复对性能的影响
