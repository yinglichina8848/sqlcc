# SQL 解析器模块测试覆盖率改进计划

## 1. 概述

本计划旨在提高SQL解析器模块的测试覆盖率，确保所有核心功能和边界情况都得到充分测试。通过系统性地分析现有测试覆盖情况，识别覆盖率缺口，并制定相应的测试策略来提高整体质量。

## 2. 当前状态分析

### 2.1 代码结构

SQL解析器模块主要包含以下组件：

| 组件类型 | 主要文件 | 功能描述 |
|---------|---------|---------|
| 核心解析器 | lexer.cpp, parser.cpp | 词法分析和语法分析 |
| AST节点 | ast_node.cpp, ast_nodes.cpp | 抽象语法树节点定义和实现 |
| 约束 | constraint.cpp, constraint_validators.cpp | 表约束处理 |
| 窗口函数 | window_function.cpp | 窗口函数支持 |
| 数据类型 | datetime.cpp, decimal.cpp | 特殊数据类型处理 |
| JSON支持 | json.cpp | JSON数据处理 |
| 集合操作 | set_operation.cpp | UNION/INTERSECT/EXCEPT等集合操作 |
| 递归查询 | recursive_query.cpp | 递归查询支持 |

### 2.2 现有测试覆盖情况

当前测试主要集中在以下方面：
- 基础SQL语句解析
- 错误处理
- 基本的词法分析功能

通过初步分析，以下区域可能存在覆盖率缺口：

1. **约束处理**：外键约束、检查约束等高级约束功能
2. **窗口函数**：窗口函数的完整语法和语义
3. **JSON处理**：JSON数据类型和操作
4. **集合操作**：UNION/INTERSECT/EXCEPT的各种变体
5. **递归查询**：递归CTE的完整支持
6. **特殊数据类型**：日期时间、十进制等复杂数据类型
7. **边界情况**：极端长度的标识符、复杂嵌套查询等

## 3. 测试覆盖率改进策略

### 3.1 优先级划分

根据功能重要性和复杂度，将测试覆盖率改进分为三个优先级：

| 优先级 | 组件 | 原因 |
|-------|------|------|
| 高 | 约束处理 | 数据库完整性的核心功能，错误可能导致数据不一致 |
| 高 | 窗口函数 | 分析查询的重要功能，语法复杂 |
| 中 | 集合操作 | 常见的查询组合方式 |
| 中 | JSON处理 | 现代数据库的重要功能 |
| 低 | 递归查询 | 相对较少使用，但功能复杂 |
| 低 | 特殊数据类型 | 基础功能，但边界情况复杂 |

### 3.2 测试策略

#### 3.2.1 单元测试

- **目标**：测试单个函数或类的行为
- **重点**：
  - 词法分析器的各种状态转换
  - 语法分析器的特定语法规则
  - AST节点的创建和操作
  - 约束验证器的验证逻辑

#### 3.2.2 集成测试

- **目标**：测试多个组件协同工作的能力
- **重点**：
  - 完整SQL语句的解析过程
  - 错误恢复机制
  - 复杂查询的处理流程

#### 3.2.3 边界测试

- **目标**：测试极端情况和边缘条件
- **重点**：
  - 超长标识符和字符串
  - 深度嵌套的查询结构
  - 复杂的窗口函数规范
  - 边界值的数据类型处理

## 4. 具体改进计划

### 4.1 约束处理测试

**测试文件**：`tests/unit/parser/constraint_test.cpp`

**测试用例**：
- 主键约束的各种形式
- 外键约束的级联操作（ON DELETE/UPDATE）
- 检查约束的表达式验证
- 唯一约束和非空约束
- 复合约束
- 约束名称的处理

### 4.2 窗口函数测试

**测试文件**：`tests/unit/parser/window_function_test.cpp`

**测试用例**：
- 基本窗口函数（ROW_NUMBER, RANK, DENSE_RANK）
- 聚合窗口函数（SUM, AVG, COUNT）
- 窗口规范（PARTITION BY, ORDER BY）
- 窗口框架（FRAME）定义
- 命名窗口
- 复杂的窗口函数组合

### 4.3 JSON处理测试

**测试文件**：`tests/unit/parser/json_test.cpp`

**测试用例**：
- JSON字面量解析
- JSON路径表达式
- JSON函数调用
- 复杂JSON结构的处理

### 4.4 集合操作测试

**测试文件**：`tests/unit/parser/set_operation_test.cpp`

**测试用例**：
- UNION/UNION ALL
- INTERSECT/INTERSECT ALL
- EXCEPT/EXCEPT ALL
- 集合操作的优先级
- 包含集合操作的复杂查询

### 4.5 递归查询测试

**测试文件**：`tests/unit/parser/recursive_query_test.cpp`

**测试用例**：
- 基本递归CTE
- 多层递归
- 递归终止条件
- 包含递归CTE的复杂查询

### 4.6 特殊数据类型测试

**测试文件**：`tests/unit/parser/data_types_test.cpp`

**测试用例**：
- 日期时间格式的各种变体
- 十进制数的精度和缩放
- 大数值的处理
- 二进制数据类型

## 6. 覆盖率衡量

使用Bazel的覆盖率工具来衡量改进效果：

```bash
bazel coverage //tests/unit/parser:parser_unit_tests --combined_report=lcov
genhtml -o coverage_report bazel-out/_coverage/_coverage_report.dat
```

**目标覆盖率**：
- 核心解析器：90%+
- 约束处理：85%+
- 窗口函数：85%+
- 其他组件：80%+

## 7. 质量保障

- 所有新测试必须通过现有测试套件
- 测试代码必须遵循项目的编码规范
- 测试用例应该有清晰的描述和预期结果
- 定期运行覆盖率测试以监控进展

## 8. 结论

通过系统性地提高SQL解析器模块的测试覆盖率，我们可以确保：
1. 核心功能的正确性
2. 边界情况的处理
3. 错误恢复机制的有效性
4. 整体代码质量的提升

这个计划将帮助我们构建一个更可靠、更健壮的SQL解析器，为上层应用提供更好的支持。
