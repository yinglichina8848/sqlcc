# v1.1.2 原始分配（raw allocations）审计报告

日期: 2025-12-12

概述
- 目标：在代码库中定位直接使用 `new`/`delete`、`malloc`/`free`、裸指针作为资源所有者等模式，给出优先级建议与整改建议。
- 方法：对 `src/`、`include/`、`tests/` 中常见源文件扩展名进行正则扫描（`new`, `delete`, `malloc`, `free`, `realloc`, `calloc`），并抽取若干代表性代码片段。

重要发现（优先级按风险/频率排序）

1) `src/bin/isql_main.cpp` — `readline` 返回的内存由 `free()` 释放

代码片段：

```cpp
// 读取输入
#ifdef USE_READLINE
  char *line = readline("");
  if (line == nullptr) { /* ... */ }
  input = line;
  free(line);
  if (!input.empty()) add_history(input.c_str());
#endif
```

问题/建议：
- 该模式本身没有直接泄漏（`free` 被调用），但手工 `free` 更容易在出错路径或异常发生时漏掉。建议：
  - 使用 `std::string` 代替裸 `char*`（`input = line; free(line);` 可被 `std::string` 包装）；
  - 或用 RAII 包装：`std::unique_ptr<char, decltype(&free)> line_guard(line, &free);` 以确保异常安全；
  - 若使用 `readline`，考虑封装一个小工具函数返回 `std::string`。

2) `tests/client_server/client_server_integration_test.cpp` — 测试代码中使用 `new`/`delete` 管理整套服务对象

代码片段：

```cpp
// 创建服务器管理器并启动服务器
server_manager_ = new ServerManager(server_path_, port_);
...
delete server_manager_;
server_manager_ = nullptr;

// 创建客户端测试对象
client_test_ = new ClientTest(client_path_, "127.0.0.1", port_);
// 在 TearDown 中 delete client_test_
```

问题/建议：
- 测试代码频繁使用裸 `new`/`delete`。测试代码容错、早退出和断言失败时容易导致内存未释放。建议：
  - 改用 `std::unique_ptr<ServerManager>` / `std::unique_ptr<ClientTest>`，或将这些对象作为测试夹具成员按 RAII 管理；
  - 对于需要跨测试生命周期共享的对象，使用 `std::shared_ptr`（仅当真的需要共享）并在 `SetUp`/`TearDown` 中通过智能指针管理生命周期。

3) `src/bin/isql_main.cpp` 中也存在直接使用 `free` 的场景（见上），可统一为 RAII 风格。

4) OpenSSL 资源释放

在 `src/network/encryption.cpp` 中看到对 `EVP_CIPHER_CTX_free(ctx)` 的调用：这是正确的显式释放；但请确认对所有 OpenSSL 结构体均有对应的释放路径（`EVP_PKEY_free`，`RSA_free`，`BIO_free` 等）。建议把 OpenSSL 对象通过小 RAII wrapper 或 `std::unique_ptr` + 自定义释放器封装。

5) 测试/bench/perf 代码里大量 `new`/`delete`

- 许多 `tests/` 下的集成/性能测试直接用 `new` 申请对象并在测试末尾 `delete`，测试代码仍然值得改造，但优先级次于生产代码的资源管理改造。

6) 第三方/外部目录（`bazel-sqlcc` / `external`）中也有大量 `new`/`malloc`，这些属于第三方代码（GoogleTest、bazel 工具等），无需在本次审计中修改。

总体建议（优先级与改造方法）
- 优先级 HIGH：生产代码中对裸资源所有权的用法（例如跨模块裸指针、手工 free、手工 delete）
  - 目标：将生产代码中直接拥有资源的裸指针替换为智能指针或 RAII 封装；把 `char*`/C 缓冲改为 `std::string`/`std::vector<char>`。
  - 工具：使用 `clang-tidy` 的 `modernize-use-unique-ptr`、`cppcoreguidelines-avoid-magic-numbers` 等自动建议，人工复审并逐步提交小范围 PR。

- 优先级 MEDIUM：测试代码中 `new`/`delete`（改造收益高但风险低）
  - 目标：将测试中的裸 `new`/`delete` 改为 `std::unique_ptr` 或在测试夹具生命周期内分配为成员变量。

- 优先级 MEDIUM：OpenSSL / C API 资源（需要逐一校验是否都有对应释放）
  - 目标：为常用 OpenSSL 类型编写小型 RAII wrapper（例如 `using EVP_CIPHER_CTX_uptr = std::unique_ptr<EVP_CIPHER_CTX, decltype(&EVP_CIPHER_CTX_free)>;`）

```cpp
// helper: 从 readline() 获取字符串并自动释放
static std::string ReadlineToString() {
  char* line = readline("");
  if (!line) return std::string();
  std::string s = line;
  free(line);
  return s;
}
```
