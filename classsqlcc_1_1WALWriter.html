详细描述

SQLCC WAL预写日志写入器 - 数据库ACID持久性保障的核心组件

WHY层 - 设计意图： WAL（Write-Ahead Logging）是现代数据库系统的核心机制，确保数据不会因系统崩溃而丢失。 通过"先写日志，再修改数据"的策略，保证了事务的持久性和原子性。 WAL写入器作为独立的异步组件，解耦了事务处理和磁盘I/O，提升了整体性能。

WHAT层 - 功能说明： 负责将内存中的WAL缓冲区日志记录持久化到磁盘文件，支持异步批量写入。 提供日志截断、同步刷新等管理功能，支持崩溃恢复和检查点操作。 实现了高性能的日志写入，通过批处理和异步I/O减少事务延迟。

HOW层 - 实现细节： 使用独立工作线程处理日志写入，避免阻塞主事务线程。 通过LSN（Log Sequence Number）维护日志顺序，确保恢复时序正确。 支持组提交优化，多个事务的日志可以批量写入，减少磁盘同步开销。 采用双缓冲机制，前台缓冲区接收新日志，后台缓冲区进行磁盘写入。

并发安全保证：

  • 工作线程独立处理I/O，不影响主事务处理
  • 缓冲区队列使用锁保护，保证多生产者-单消费者模式安全
  • LSN原子递增，确保全局日志顺序
  • 文件操作加锁，防止并发写入冲突

性能优化策略：

  • 异步写入：事务提交不等待磁盘I/O完成
  • 批量处理：积累多个日志记录后一次性写入
  • 组提交：多个事务可以共享一次磁盘同步
  • 预分配：日志文件预分配空间，减少动态扩展开销

故障恢复机制：

  • 日志截断：检查点后清理过期日志，节省存储空间
  • 顺序重放：按LSN顺序重做未完成的事务
  • 一致性检查：验证日志完整性和数据一致性
注解
WAL是数据库系统中最复杂的组件之一，涉及并发、性能、可靠性的综合权衡
异步写入可能导致少量日志丢失，但通过配置可以调整同步策略
LSN是全局递增的序列号，用于标识日志记录的顺序关系
参见
docs/design/storage_engine/wal_system_design.md 详细的WAL系统设计文档，包含完整的算法分析和故障恢复流程

启动WAL写入器 - 激活异步日志写入机制

WHY层 - 设计意图： WAL写入器的启动标志着数据库进入事务处理状态。 异步写入线程的启动是性能优化的关键，使事务提交不再等待磁盘I/O。

WHAT层 - 功能说明： 打开WAL文件，启动工作线程，开始接受日志写入请求。 初始化运行状态标志，准备统计信息收集。

HOW层 - 实现细节：

  1. 打开WAL文件，创建文件流对象
  2. 设置running_标志为true
  3. 创建并启动工作线程WALWriteWorker
  4. 初始化写入队列和条件变量
  5. 记录启动时间戳和初始统计信息

线程安全保证：

  • 启动操作是原子的，不会被并发调用
  • 工作线程独立运行，不影响主线程
  • 状态标志使用原子操作保证可见性

性能影响：

  • 启动后事务提交延迟显著降低
  • 系统资源消耗增加（一个额外线程）
  • I/O性能提升（异步批处理）
注解
必须在数据库启动序列中调用
重复调用Start()是安全的（无操作）
启动后立即可以接受写入请求

停止WAL写入器 - 优雅关闭异步日志系统

WHY层 - 设计意图： WAL写入器的停止必须保证数据完整性，防止日志丢失。 优雅停止避免强制终止可能导致的数据不一致。

WHAT层 - 功能说明： 停止工作线程，处理所有待写入日志，关闭文件。 确保所有缓冲的数据都被持久化到磁盘。

HOW层 - 实现细节：

  1. 设置running_标志为false，通知工作线程退出
  2. 通过条件变量唤醒工作线程
  3. 等待工作线程完成所有待处理任务
  4. 强制同步所有缓冲数据到磁盘
  5. 关闭WAL文件，释放系统资源

数据完整性保证：

  • 工作线程会处理完所有队列中的写入请求
  • 强制同步确保数据到达磁盘
  • 文件关闭前进行完整性检查

阻塞行为：

  • Stop()会阻塞直到所有数据安全写入
  • 在高负载情况下可能需要几秒钟
  • 这是数据库关闭时的必要等待
注解
必须在数据库关闭序列中调用
重复调用Stop()是安全的（无操作）
调用后写入器进入不可用状态

bool sqlcc::WALWriter::Sync ( )

同步WAL文件到磁盘 - 强制数据持久化

WHY层 - 设计意图： WAL同步是ACID属性的D（持久性）保证的关键。 允许应用程序控制数据持久化的时机，平衡性能和可靠性。

WHAT层 - 功能说明： 强制将所有缓冲的WAL数据刷新到磁盘，确保数据不会因系统崩溃而丢失。 阻塞调用，直到所有数据都被确认写入持久存储。

HOW层 - 实现细节：

  1. 获取文件锁，保证同步操作的原子性
  2. 调用文件系统的fsync()或等效操作
  3. 等待磁盘确认数据已持久化
  4. 更新统计信息（同步计数和时间）
  5. 返回同步结果状态

同步策略选择：

  • 立即同步：每次提交都同步（高可靠性，低性能）
  • 定期同步：每隔一段时间同步一次（平衡选择）
  • 组提交：多个事务共享一次同步（高性能）

性能影响：

  • 同步操作通常需要几毫秒到几十毫秒
  • 会阻塞调用线程
  • 频繁同步会显著降低吞吐量

使用场景：

  • 关键事务提交后需要立即确认持久化
  • 系统关闭前的最终数据刷新
  • 应用程序需要强一致性保证时
返回
是否成功同步所有数据到磁盘
注解
这是一个阻塞操作，会等待磁盘I/O完成
同步失败通常表示严重的磁盘或文件系统错误
成功同步后，即使系统崩溃也不会丢失数据

WAL写入工作线程函数

WAL 写入工作线程

WHY: 磁盘写入是阻塞且缓慢的。为了防止 fsync 拖慢正常的事务处理流程， 必须使用独立的后台线程来负责物理 I/O。 WHAT: 实现一个“消费循环”，从待写入队列中提取批次并顺序落盘。 HOW:

  1. 挂起等待：使用 write_cv_ 在没有任务时进入低功耗休眠。
  2. 批量提取：一旦被唤醒，使用 swap 技术一次性提取 write_queue_ 中积累的所有批次。
  3. 顺序落盘：遍历批次，调用 PerformWrite 将数据流式写入文件。
  4. 退出协议：当 running_ 为 false 时，必须先处理完剩余的所有队列数据再安全退出。

写入WAL记录到磁盘 - WAL系统的核心API

WHY层 - 设计意图： 这是WAL机制的核心接口，保证事务的持久性。 通过异步批处理写入，平衡了可靠性和性能。

WHAT层 - 功能说明： 将一组WAL记录提交给写入器，异步持久化到磁盘。 支持批量写入优化，减少I/O操作次数。

HOW层 - 实现细节：

  1. 验证写入器运行状态
  2. 创建记录副本，添加到写入队列
  3. 通知工作线程处理新请求
  4. 更新统计信息（写入计数等）
  5. 返回成功状态（不等待实际写入完成）

异步处理机制：

  • 主线程立即返回，不等待磁盘I/O
  • 工作线程在后台批量处理写入
  • 通过队列解耦生产者和消费者

错误处理：

  • 写入器未启动时返回false
  • 队列满时可以选择阻塞或返回错误
  • 工作线程处理磁盘I/O错误

性能优化：

  • 批量处理减少系统调用次数
  • 异步处理避免事务阻塞
  • 内存拷贝最小化
参数
recordsWAL记录列表，包含需要持久化的日志条目
返回
是否成功提交到写入队列（不代表已写入磁盘）
注解
这是一个异步操作，成功返回不意味着数据已持久化
批量写入可以显著提升性能
记录顺序由LSN保证，不依赖提交顺序
